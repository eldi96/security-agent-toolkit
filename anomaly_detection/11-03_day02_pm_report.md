## 5교시 · 정규화된 이벤트를 표로 읽고 실패만 골라 세기

### 문제 5-1 · 정규화된 이벤트 표를 읽어 실패한 이벤트를 소스별로 세기

- (가) 실행한 출력 전체를 붙여 넣고, 표의 행 수와 열 수, 성공과 실패 개수, 실패한 이벤트의 소스별 개수를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 행 수 · 열 수와 성공 · 실패 개수 ③ 소스별 실패 개수
  - 답:
    - ① 아래 코드 상자의 출력 전체
    - ② 57행 6열이고, 성공 34개 · 실패 23개입니다.
    - ③ web 13개, server 9개, saas 1개입니다.

```
--- 단계 1: 표 크기(행 수, 열 수)와 처음 3개 시각
(57, 6)
2026-11-02 02:14:08
2026-11-02 09:01:05
2026-11-02 09:01:06
--- 단계 2: 성공 · 실패별 개수
result
성공    34
실패    23
Name: count, dtype: int64
--- 단계 3: 실패한 이벤트 23 개의 소스별 개수
source
web       13
server     9
saas       1
Name: count, dtype: int64
--- 단계 4: 전체 이벤트의 소스별 개수
source
web       28
server    15
saas      14
Name: count, dtype: int64
```

- (나) 🔍 실패 개수만 보면 web 이 가장 많습니다. 그렇다면 web 이 가장 문제가 큰 소스라고 말할 수 있을까요? 단계 4의 전체 이벤트 수와 함께 보고 이유를 적어 주세요.
  - 쓸 내용: ① 말할 수 있는지 없는지 ② 소스마다 전체 이벤트 수가 다르다는 것을 근거로 한 이유
  - 답:
    - ① 실패 개수만으로는 말할 수 없습니다.
    - ② 소스마다 전체 이벤트 수가 달라서 실패 개수를 그대로 비교할 수 없습니다. 단계 4의 전체 수로 실패 비율을 구하면 web 은 13/28(약 46%), server 는 9/15(60%), saas 는 1/14(약 7%)입니다. web 은 실패 개수가 가장 많지만 전체 이벤트도 가장 많고, 비율은 server 가 더 높습니다. 그래서 전체 이벤트 수와 함께 봐야 합니다.

- (다) 🔍 web 이벤트에는 `user` 가 비어 있습니다. 사용자 이름으로 실패를 세려 할 때 web 의 실패 13개는 어떻게 될지 예상하고, 사용자 대신 어떤 열을 보면 같은 대상이 반복했는지 알 수 있을지 이유와 함께 적어 주세요.
  - 쓸 내용: ① 사용자 이름으로 셀 때 web 실패 13개가 어떻게 될지 ② 대신 볼 열과 그 이유
  - 답:
    - ① web 이벤트는 `user` 가 비어 있어서 13개 모두 어느 사용자에게도 세어지지 않고 결과에서 빠질 것입니다.
    - ② `ip` 열을 봅니다. web 실패 13개는 모두 `ip` 값이 있어서, 같은 IP 가 반복되면 같은 대상이 반복했다고 추정할 수 있습니다. 실제로 세어 보면 `203.0.113.50` 이 7개, `198.51.100.90` 이 3개입니다.

## 6교시 · 실패를 사용자별 · 시간대별로 묶어 세고 저장하기

### 문제 6-1 · 실패한 이벤트를 사용자별 · 시간대별로 묶어 세고 CSV 로 저장하기

- (가) 실행한 출력 전체를 붙여 넣고, 실패가 가장 많은 사용자와 횟수, 실패가 가장 많이 난 시간대와 횟수, 저장된 행 수를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 실패가 가장 많은 사용자와 횟수 ③ 가장 많이 난 시간대와 횟수 ④ 저장된 행 수
  - 답:
    - ① 아래 코드 상자의 출력 전체
    - ② `dami`, 4회입니다.
    - ③ 9시, 13회입니다.
    - ④ 23행입니다.

```
--- 단계 1: 사용자별 실패 횟수
user
dami       4
gaeun      3
seoyeon    2
jiwoo      1
dtype: int64
--- 단계 2: 시간대별 실패 횟수
hour
2      1
9     13
10     3
11     5
18     1
dtype: int64
--- 단계 3: 저장한 파일 failed_events.csv
저장된 행 23 개
```

- (나) 🔍 시간대별 결과에서 실패가 가장 많이 난 시간대의 개수를 보세요. 이 개수는 5교시 단계 3의 어느 소스 개수와 같은가요? 그 실패가 어느 소스에서 났는지 적고(근거는 숫자가 같다는 것까지 쓰면 됩니다), 이어서 확인할 것도 적어 주세요.
  - 쓸 내용: ① 많이 난 실패가 어느 소스에서 난 것인지와 그 근거 ② 이어서 확인할 것
  - 답:
    - ① web 에서 난 실패입니다. 9시의 실패 13개가 5교시 단계 3의 web 실패 13개와 숫자가 같습니다. `failed_events.csv` 에서 `hour` 가 9 인 행의 `source` 도 모두 web 이었습니다.
    - ② 9시 web 실패를 `ip` 와 `action` 으로 나눠 같은 IP 가 반복했는지, 어떤 요청이 실패했는지 확인합니다. 특히 7개로 가장 많은 `203.0.113.50` 이 `POST /login` 을 3초 간격으로 5번 실패한 뒤 `GET /admin` 까지 요청했으므로, 공격 시도인지 조사합니다.

- (다) 🔍 사용자별 실패 횟수를 모두 더하면 실패한 이벤트 전체보다 적습니다. 몇 개가 모자라고 왜 모자란지 적어 주세요. 그리고 이 차이를 모르고 사용자별 숫자만 보면 어떤 잘못된 판단을 할 수 있을지도 적어 주세요.
  - 쓸 내용: ① 몇 개가 모자란지 ② 모자란 이유 ③ 모르고 넘어가면 생기는 잘못된 판단
  - 답:
    - ① 13개가 모자랍니다. 사용자별 합계는 4 + 3 + 2 + 1 = 10개이고, 실패한 이벤트 전체는 23개입니다.
    - ② web 실패 13개는 `user` 가 비어 있는데, `groupby` 는 비어 있는 값의 행을 빼고 세기 때문입니다.
    - ③ 실패가 10개뿐이고 `dami`(4회)가 가장 큰 문제라고 잘못 판단할 수 있습니다. 실제로는 실패의 절반이 넘는 13개가 집계에서 빠져 있고, `dami` 보다 많은 7개를 실패한 IP `203.0.113.50` 도 놓치게 됩니다.
