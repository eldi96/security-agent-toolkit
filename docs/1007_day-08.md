# Day 08. JSON 요약에서 Markdown 보고서 만들기

> 2026-10-07 · AI 자동화를 위한 Python

## 오늘의 학습

JSON에 저장된 경보 요약을 읽어 Markdown 보고서로 만드는 방법을 배웠다. f-string과 줄바꿈으로 목록을 조립하고, 보고서 생성·저장 기능을 함수로 분리했다. 많은 경보는 슬라이싱으로 배치 처리하고, LLM의 총평과 코드가 계산한 수치를 조합해 일정한 보고서 형식을 유지했다.

## 학습 내용

### JSON 결과를 사람이 읽는 보고서로

전날 만든 에이전트 결과는 기계가 읽기 좋은 JSON 형태였다. 이번에는 이 데이터를 사람이 확인하기 쉬운 Markdown 보고서로 바꾸는 작업을 했다. `json.load()`로 요약 목록을 읽고, 반복문과 f-string으로 경보별 위험도·식별자·요약 문장을 한 줄씩 조립했다. `\n`을 넣어 목록의 줄바꿈을 만들고 `"w"`, `"a"` 모드로 파일 저장 방식을 구분했다.

### 위험도 정렬과 배치 처리

경보를 시간 순서대로 나열하는 대신 높은 위험도부터 보여주도록 순서를 조정했다. 위험도 문자열은 `.lower()`나 `.upper()`로 표기를 통일해 비교하거나 출력했다. 정렬한 목록을 Markdown으로 만드는 과정에서 반복문 안에 또 반복문이 들어가면 전체 순회 횟수가 늘어난다는 점도 확인했다.

많은 경보를 한 번에 LLM에 전달하면 입력 길이 제한에 걸리거나 일부를 놓칠 수 있다. 그래서 리스트 슬라이싱과 `range()`를 이용해 일정한 개수씩 배치로 나누었다. `[a:b]`에서 `b`는 포함되지 않으며, 각 배치 결과는 이후에 다시 모아야 한다.

### 함수별 역할 분리와 LLM 총평

`make_lines()`는 경보 목록 문자열, `make_overview()`는 LLM 총평, `build_report()`는 최종 문서 구성, `save_report()`는 파일 저장처럼 역할을 나눴다. 숫자 집계는 Python 코드가 수행하고, 설명 문장은 LLM이 작성하도록 구분하면 보고서 형식을 일정하게 유지하기 쉽다.

Colab에서 `%%writefile`로 `.py` 파일을 수정한 뒤 이미 불러온 모듈을 다시 적용하려면 `importlib.reload()`가 필요할 수 있다. 또한 함수 내부에서 문자열을 만들기만 하고 `return`하지 않으면 호출한 쪽에서는 `None`을 받게 된다. 빈 문자열 `""`과 `None`도 서로 다른 값이므로 실패 처리에서 구분해야 한다.

## 실습 흐름

JSON 읽기 → 요약 목록 생성 → Markdown 구성 → 함수 반환·저장 → 배치 처리 → LLM 총평 결합

## 기억할 코드

**요약 목록 만들기**

```python
lines = ""
for s in sorted_summaries:
    lines += f"- [{s['risk_level'].upper()}] {s['summary']}\n"
```

**배치 나누기**

```python
batch_size = 6
for start in range(0, len(items), batch_size):
    batch = items[start:start + batch_size]
```

## 실습에서 연결된 내용

결과적으로 **JSON 읽기 → 위험도 기준 정리 → Markdown 목록 생성 → 배치별 LLM 총평 → 보고서 조립·저장** 흐름을 만들었다. 전체를 LLM에 맡기기보다 수치와 형식은 코드가 관리하고, 문장 생성에 LLM을 사용하는 방식이 핵심이었다.

## 오늘 막혔던 부분

일부만 출력한 문자열의 전체 길이가 왜 더 큰지 질문했고, 슬라이싱은 출력 범위만 제한한다는 점을 확인했다. `build_report()`가 `None`을 반환했던 것은 함수 끝에 `return report`가 없었기 때문이었다. 슬라이싱의 끝 인덱스가 포함되지 않는 규칙도 다시 정리했다.
