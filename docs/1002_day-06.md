# Day 06. Flask 웹훅 서버와 명령줄 실행

> 2026-10-02 · AI 자동화를 위한 Python

## 오늘의 학습

경보를 전달하는 폴링과 웹훅의 차이를 배웠다. Flask로 요청을 받는 서버와 라우트를 만들고, `curl`로 HTTP 요청을 보내 테스트했다. Bash 스크립트로 명령을 묶고 `argparse`로 포트·룰 같은 실행 옵션을 전달하는 과정까지 연결했다.

## 학습 내용

### 폴링과 웹훅의 차이

보안 경보를 받는 방법으로 폴링과 웹훅을 비교했다. 폴링은 내 프로그램이 주기적으로 새 경보가 있는지 묻는 방식이고, 웹훅은 이벤트가 발생했을 때 상대 시스템이 지정된 주소로 요청을 보내는 방식이다. 웹훅을 받으려면 HTTP 요청을 처리할 서버가 실행 중이어야 한다.

### Flask로 서버와 경로 만들기

클라이언트는 요청을 보내는 쪽, 서버는 요청을 받아 처리하고 응답하는 쪽이다. Flask에서 `app = Flask(__name__)`으로 앱을 만들고 라우트에 URL 경로와 메서드를 연결했다. 요청 본문에 담긴 JSON을 읽고 응답으로 돌려주는 실습을 통해 서버가 어떻게 데이터를 받는지 확인했다.

`127.0.0.1`은 현재 컴퓨터를 가리키는 루프백 주소다. `http://127.0.0.1:5001/webhook`에서 포트는 실행 중인 서버 프로그램을 구분하고 `/webhook`은 요청을 처리할 경로를 뜻한다. 서버가 켜져 있지 않으면 URL 형식이 맞더라도 연결할 수 없다.

### curl·Bash·argparse 연결

`curl`로 POST 요청을 보내 웹훅 서버를 테스트했다. HTTP 응답을 받은 것과 서버에 아예 연결하지 못한 상황을 구분하는 과정이 필요했다. 반복되는 명령은 Bash 스크립트(`.sh`)로 묶었고, Python 스크립트(`.py`)와 Bash 명령은 서로 다른 문법으로 실행된다는 점을 확인했다.

`argparse`는 실행할 때 `--port`, `--rule`처럼 옵션 값을 전달받기 위한 도구다. 옵션을 정의하는 것만으로 서버 포트가 바뀌는 것은 아니며, 파싱한 값을 `app.run(port=args.port)` 같은 실행 코드에 전달해야 적용된다.

### 실습 파일 관리

서버·테스트 스크립트·룰 파일을 저장소로 관리하는 과정에서 Git의 `commit`, `merge`, `stash`, `push` 역할도 실제로 확인했다. 특히 로컬 작업물을 보존하면서 원격 저장소의 변경과 합치는 순서가 중요했다.

## 실습 흐름

경보 발생 → 폴링·웹훅 비교 → Flask 서버 → curl 테스트 → Bash → argparse → GitHub 정리

## 기억할 코드

**웹훅 수신 라우트**

```python
from flask import Flask, request, jsonify
app = Flask(__name__)

@app.post("/webhook")
def webhook():
    return jsonify({"received": request.get_json()})
```

**실행 인자 받기**

```python
import argparse
parser = argparse.ArgumentParser()
parser.add_argument("--port", type=int, default=5001)
args = parser.parse_args()
```

## 실습에서 연결된 내용

로그 분석에서 경보를 만드는 데서 한 단계 더 나아가, **그 경보를 HTTP로 받아 처리하는 서버**를 만들었다. 서버를 실행하는 터미널과 테스트 요청을 보내는 터미널의 역할이 다르며, 요청이 실패할 때는 먼저 서버 실행 상태와 포트를 확인해야 한다는 점이 남았다.

## 오늘 막혔던 부분

`curl`에서 `HTTP 000`이 나왔을 때 명령 오류인지 서버 미실행인지 구분하는 과정을 거쳤다. `--port`는 인자를 받도록 정의하는 단계이고 실제 서버 포트 적용은 별도 코드에서 이뤄진다는 점을 확인했다. Bash 명령과 Python 코드는 실행 방식이 다르다는 점도 정리했다.
