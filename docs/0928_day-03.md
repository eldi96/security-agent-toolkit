# Day 03. 예외 처리와 로그 데이터 정규화

> 2026-09-28 · AI 자동화를 위한 Python

## 오늘의 학습

실제 로그에는 파일 누락, 칸 부족, 숫자 변환 실패 같은 문제가 생길 수 있다는 점을 배웠다. `try/except`로 예외를 처리하고 `logging`으로 상황을 기록했다. 이후 CSV 문자열을 나누고 딕셔너리로 바꾼 뒤, 중첩 구조와 JSON을 사용해 데이터를 저장하는 과정을 실습했다.

## 학습 내용

### 오류를 처리하고 기록 남기기

로그 파일을 읽을 때 파일이 없거나, 행에 필요한 칸이 부족하거나, 문자열을 숫자로 바꿀 수 없는 문제가 발생할 수 있다. 각각 `FileNotFoundError`, `IndexError`, `ValueError`처럼 서로 다른 예외로 나타난다. `try/except`는 문제가 생길 수 있는 코드를 실행하고 지정한 예외가 발생했을 때 대체 동작을 수행하는 구조다.

오류를 처리하는 것과 원인을 남기는 것은 별개라서 `logging`도 함께 사용했다. `DEBUG`, `INFO`, `WARNING`, `ERROR` 등 수준에 따라 기록을 구분하고, 시간·수준·메시지를 파일에 남길 수 있다. Traceback은 오류가 발생한 위치와 호출 흐름을 알려주므로 아래쪽의 예외 종류와 메시지부터 확인하는 습관을 정리했다.

### 문자열을 구조화된 로그로 변환

CSV처럼 구분자가 있는 로그는 `split(",")`으로 나누면 리스트가 된다. 여기에 `zip()`으로 항목 이름을 짝지은 뒤 `dict()`로 변환하면 `time`, `user`, `event`, `ip` 같은 키를 가진 딕셔너리로 만들 수 있다. 변환 과정에서 필요한 항목을 빠뜨린 줄은 건너뛰거나 별도로 기록해야 한다.

딕셔너리 안에 다시 딕셔너리가 있는 중첩 구조도 살펴봤다. 예를 들어 사용자별 성공·실패 횟수를 저장하면 먼저 사용자 키를 선택하고, 그 안에서 `fail` 키를 다시 선택해야 한다. 대괄호가 연속해서 등장하는 이유는 **한 번에 두 값을 찾는 게 아니라 단계별로 안쪽 구조에 들어가기 때문**이다.

### JSON과 정규화

JSON은 프로그램 사이에서 데이터를 주고받거나 저장할 때 자주 쓰는 형식이다. `json.load()`는 파일에서 읽고, `json.loads()`는 JSON 문자열을 읽는다. 반대로 `dump()`와 `dumps()`는 Python 데이터를 JSON으로 내보낼 때 사용한다. 로그마다 표현이 다르면 이후 집계가 어려우므로 같은 키와 값 형식으로 맞추는 **정규화**를 진행했다.

## 실습 흐름

오류 확인 → 예외 처리 → 로그 기록 → 문자열 분리 → 딕셔너리 변환 → JSON 저장

## 기억할 코드

**깨진 로그 건너뛰기**

```python
try:
    count = int("abc")
except ValueError:
    print("숫자로 변환할 수 없음")
```

**문자열을 딕셔너리로 정리**

```python
keys = ["time", "user", "event"]
values = "09:12,admin,login_fail".split(",")
row = dict(zip(keys, values))
```

## 실습에서 연결된 내용

실습의 핵심은 단순히 로그 한 줄을 출력하는 것이 아니라 **원본 문자열을 읽고 → 필요한 값을 분리하고 → 딕셔너리로 만들고 → 일관된 형식으로 저장하는 과정**이었다. 처리에 실패한 줄도 프로그램 전체를 멈추게 하지 않고 구분해 다루는 것이 중요했다.

## 오늘 막혔던 부분

중첩 딕셔너리에서 `report["admin"]["fail"]`처럼 대괄호를 연속해서 사용하는 과정이 헷갈렸다. 안쪽 값이 다시 딕셔너리라는 점을 확인하고, 문자열을 `split()`으로 리스트로 만든 다음 `zip()`과 `dict()`로 키·값을 연결하는 흐름을 따라가며 이해했다.
