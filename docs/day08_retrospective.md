# 1과목 회고 (전병현)

## 내가 만든 것
- Python의 기본 문법부터 시작해 CSV와 JSON 데이터를 읽고 가공하는 코드를 작성했다.
- 로그 데이터를 파싱하고 정규화한 뒤, 로그인 실패 횟수나 심야 접속 같은 조건을 기준으로 경보를 발생시키는 탐지 룰을 만들었다.
- 외부 API를 호출해 필요한 정보를 조회하고, Flask로 웹훅 서버를 만들어 알림을 주고받는 실습을 진행했다.
- LLM API와 여러 도구를 연결해 경보를 분석하고, 위험한 작업은 사람의 승인을 거치도록 하는 에이전트 구조를 구현했다.
- 마지막에는 분석 결과를 Markdown 보고서로 저장하고, 알림 전송까지 하나의 파이프라인으로 연결했다.

## 가장 어려웠던 것
- 처음에는 리스트와 딕셔너리의 구조를 이해하고, 중첩된 데이터에서 원하는 값을 꺼내는 과정이 어려웠다.
- 특히 `split()`, `zip()`, `dict()`를 거치면서 문자열이 리스트와 딕셔너리로 바뀌는 흐름을 따라가는 데 시간이 걸렸다.
- 정규표현식에서는 여러 기호와 그룹이 어떤 범위의 문자를 추출하는지 구분하는 것이 헷갈렸다.
- 에이전트 실습에서는 Registry와 Router의 역할이 쉽게 이해되지 않았다. 여러 번 질문하면서 LLM은 도구를 선택하고, 실제 함수 실행은 Python 코드가 담당한다는 구조를 이해했다.
- 단순한 문법보다 여러 함수가 연결되었을 때 데이터가 어디에서 만들어지고, 어떤 형태로 전달되며, 어디에서 반환되는지를 파악하는 과정이 가장 어려웠던 것 같다.

## 리뷰에서 찾은 것과 고친 것
- 코드가 오류 없이 실행된다고 해서 결과까지 올바른 것은 아니라는 점을 알게 되었다.
- 함수 안에서 결과를 만들었지만 `return`을 작성하지 않아 `None`이 반환되는 문제를 확인했다.
- 파일이나 딕셔너리의 값이 없을 때 발생하는 오류를 확인하고, `try / except`와 `.get()` 등을 이용해 처리하는 방법을 익혔다.
- API 요청에서는 서버가 응답하지 않을 수 있다는 점을 고려해 `timeout`과 예외 처리를 추가했다.
- 모델 이름이나 알림 주소처럼 변경될 수 있는 값은 `config.json`으로 분리하고, API 키 같은 비밀값은 코드에 직접 작성하지 않도록 점검했다.
- 마지막 코드 리뷰와 테스트를 통해 정상 실행뿐 아니라 실패 상황과 예상한 결과까지 확인하는 과정이 필요하다는 것을 배웠다.

## 캡스톤에서 더 해 보고 싶은 것
- 이번 강의에서 배운 Python, API, LLM을 활용해 실제로 반복되는 작업을 자동화하는 프로그램을 만들어 보고 싶다.
- 특히 하나의 AI가 모든 작업을 처리하기보다는 분석, 검증, 반박, 최종 판단처럼 역할을 나누고 결과를 서로 확인하는 멀티 에이전트 구조에 관심이 생겼다.
- AI가 판단한 내용을 무조건 실행하는 것이 아니라, 결과를 검증하고 위험한 작업에는 사람의 승인을 거치는 구조를 적용해 보고 싶다.
- 앞으로 배우게 될 네트워크와 보안 지식을 연결해 단순히 작동하는 프로그램을 넘어 오류와 예외 상황까지 고려한 자동화 시스템을 구현하는 것이 목표다.
