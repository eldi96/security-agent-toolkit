# Day 09. 설정 분리·안전한 알림·검증

> 2026-10-08 · AI 자동화를 위한 Python

## 오늘의 학습

오늘은 강의 노트북을 기준으로 설정값을 JSON 파일로 분리하고, 보고서 생성 뒤 웹훅으로 알림을 보내는 흐름을 다뤘다. 서버가 꺼져 있거나 요청에 실패해도 전체 작업이 중단되지 않도록 예외를 처리했다. 이어 코드 리뷰와 `assert`, Traceback 확인, 디버깅을 거쳐 전체 과정을 점검했다.

## 학습 내용

### 설정을 코드 밖으로 분리

앞서 만든 파일에는 모델 이름, 날짜, 위험도 기준처럼 바뀔 수 있는 값이 코드 안에 들어 있었다. 이런 값을 수정할 때마다 코드를 찾아 고치지 않도록 `config.json`으로 분리하는 흐름을 배웠다. `json.load()`로 설정을 딕셔너리로 읽고, `in`으로 필요한 키가 있는지 확인하며 위험도 기준을 비교하는 과정을 살펴봤다.

설정 파일을 분리한다고 모든 정보가 공개돼도 되는 것은 아니다. API 키 같은 비밀값은 일반 설정과 구분하고 공개 저장소에 포함하지 않도록 주의해야 한다.

### 보고서 완성 뒤 알림 보내기

보고서를 만드는 것에서 끝나지 않고 담당자에게 웹훅 알림을 보내는 기능을 추가했다. `requests.post(url, json={...}, timeout=5)`로 JSON 본문을 전송하고, 요청에 실패하더라도 전체 자동화가 중단되지 않도록 `try/except`를 사용했다. 알림 성공·실패를 `True`·`False`로 반환하면 호출한 쪽에서 다음 행동을 결정할 수 있다.

연결 실패처럼 예외가 발생하는 경우와 HTTP 응답이 오류 상태로 돌아오는 경우는 구분해야 한다. HTTP 오류도 실패로 처리하려면 상태코드를 검사하거나 `raise_for_status()`를 사용해야 한다. 알림 서버가 꺼져 있는 상황을 재현해 정상 흐름과 실패 흐름을 비교하는 실습이 포함되어 있었다.

### 여러 단계를 하나로 실행

이전까지는 노트북 셀을 순서대로 실행해야 보고서가 만들어졌다. 설정 읽기·데이터 처리·보고서 저장·알림 전송을 함수로 연결해 한 번의 실행으로 처리하는 구조로 정리했다. `print()`는 화면 출력, `return`은 다음 단계에 전달할 값이며 여러 결과를 딕셔너리 하나로 묶어 반환할 수 있다. `if __name__ == "__main__":`은 파일을 직접 실행했을 때 시작할 코드를 구분한다.

### 검증과 디버깅

코드가 실행된다는 사실만으로 결과가 올바르거나 안전한 것은 아니다. `assert`로 예상 조건을 확인하고, `is None`으로 값이 없는 상태를 검사했다. 문제가 생기면 Traceback의 오류 메시지와 발생 위치를 확인하고, 중간 값을 출력해 원인을 좁히는 방식을 복습했다. 마지막에는 정상 실행과 알림 실패 상황을 각각 점검하는 것으로 강의 흐름을 마무리했다.

## 실습 흐름

설정 파일 읽기 → 보고서 조건 판단 → 웹훅 알림 → 실패 기록 → 코드 검증 → 전체 흐름 점검

## 기억할 코드

**설정 파일 읽기**

```python
import json
with open("config.json", encoding="utf-8") as f:
    config = json.load(f)
```

**실패해도 중단하지 않는 알림**

```python
import requests
def notify_safe(message, url):
    try:
        requests.post(url, json={"text": message}, timeout=5).raise_for_status()
        return True
    except requests.RequestException as e:
        print("알림 실패:", e)
        return False
```

## 실습에서 연결된 내용

이날은 개별 문법보다 **설정 → 실행 → 보고서 → 알림 → 검증**을 하나의 작업으로 연결하는 데 초점이 있었다. Day 9의 개인 노션 메모는 아직 확인되지 않았으므로 이 부분은 강의 자료에 나온 흐름을 기준으로 정리했다.

## 오늘 막혔던 부분

노션 Day 9 메모는 아직 확인되지 않았다. 이전 질문에서는 `requests.post()`를 `try/except`로 감싸고 성공·실패에 따라 `True`와 `False`를 반환하는 코드를 확인했다. 요청이 예외 없이 끝나는 것과 HTTP 응답이 성공 상태인 것은 별개이므로, 성공 여부를 판단할 때 상태코드 검사도 필요하다는 점을 함께 정리했다.
