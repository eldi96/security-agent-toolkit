# Day 05. 외부 API 요청과 응답 처리

> 2026-09-30 · AI 자동화를 위한 Python

## 오늘의 학습

로그 분석 결과에 외부 정보를 보태기 위해 `requests`로 HTTP 요청을 보내는 방법을 익혔다. GET 요청의 `params`와 `headers`, 상태코드 확인, JSON 응답 변환을 다뤘다. 인증 정보와 요청 실패에 대비하고, 필요한 값만 골라 정리하는 흐름을 실습했다.

## 학습 내용

### 외부 API로 필요한 정보 가져오기

전날 만든 탐지 결과에 외부 정보를 추가하기 위해 HTTP 요청을 보내는 방법을 배웠다. 공인 IP와 사설 IP의 차이를 확인하고, IP 조회 서비스를 통해 국가·네트워크 사업자 같은 정보를 받을 수 있다는 흐름을 살펴봤다. 외부 서비스가 제공하는 정보는 응답 시점과 서비스 정책에 따라 달라질 수 있으므로 로그 원본과 구분해서 다뤄야 한다.

`requests.get()`으로 조회 요청을 보내고 `params`에 조회 조건을, `headers`에 요청 관련 정보나 인증 값을 담는 방식을 배웠다. `timeout`은 응답을 무한히 기다리지 않도록 제한하는 설정이다. HTTP 상태코드는 요청 처리 결과를 나타내며, `response.json()`은 응답 본문을 Python에서 사용할 수 있는 자료형으로 해석한다.

### 응답을 읽고 필요한 정보만 남기기

API 응답은 딕셔너리와 리스트가 중첩된 JSON일 수 있다. 전체 응답을 그대로 사용하는 대신 필요한 키를 골라 새로운 딕셔너리로 정리하는 과정을 실습했다. 응답 구조를 확인하지 않고 키에 접근하면 없는 항목 때문에 오류가 발생할 수 있어 `.get()`으로 기본값을 지정하는 방법도 연결했다.

HTTP 요청이 성공했다고 데이터의 의미까지 검증된 것은 아니다. 응답의 성공 여부, JSON 형식, 필수 키 존재 여부를 차례로 확인하는 것이 필요하다. `raise_for_status()`는 HTTP 오류 상태를 예외로 다룰 때 사용할 수 있지만, 서비스가 본문 안에 별도 실패 표시를 보내는 경우는 따로 검사해야 한다.

### 인증·실패·재시도

외부 API를 사용할 때는 키나 토큰이 필요할 수 있다. 인증 정보를 코드에 직접 적거나 공개 저장소에 올리지 않도록 분리하는 것이 중요하다. 네트워크 오류, 시간 초과, 서버 오류가 발생할 수 있으므로 `try/except`와 제한된 재시도 같은 실패 대응을 고려했다. 실패했다고 무조건 반복 호출하면 오히려 서비스에 부담을 줄 수 있다는 점도 함께 정리했다.

## 실습 흐름

IP 정보 확인 → HTTP 요청 → 상태코드 점검 → JSON 변환 → 필요한 데이터 추출 → 실패 대응

## 기억할 코드

**GET 요청과 상태 확인**

```python
import requests
response = requests.get("https://ipwho.is/8.8.8.8", timeout=5)
response.raise_for_status()
```

**JSON 응답에서 값 확인**

```python
data = response.json()
print(data.get("country"))
```

## 실습에서 연결된 내용

이날은 **요청을 보낸다 → 응답 상태를 확인한다 → JSON을 읽는다 → 필요한 필드를 추린다 → 실패에 대비한다**는 순서를 중심으로 이해했다. 단순히 `.get()`을 호출하는 것보다 응답을 신뢰할 수 있는지 확인하고 이후 분석에 쓸 데이터만 정리하는 과정이 중요했다.

## 오늘 막혔던 부분

API 요청을 보냈다고 항상 원하는 데이터가 오는 것은 아니라는 점을 확인했다. 상태코드와 응답 본문을 구분하고, 응답이 JSON이라도 필요한 키가 없을 수 있으므로 `.get()`과 예외 처리를 함께 고려하는 방식으로 정리했다.
