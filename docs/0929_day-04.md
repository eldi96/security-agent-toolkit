# Day 04. 정규표현식과 보안 탐지 룰

> 2026-09-29 · AI 자동화를 위한 Python

## 오늘의 학습

쉼표로 나뉘지 않은 비정형 로그를 처리하기 위해 정규표현식을 배웠다. `re.search()`, `re.findall()`과 그룹을 사용해 필요한 값을 추출하고, 패턴에 맞는 로그와 맞지 않는 로그를 구분했다. 정규화된 로그에는 로그인 실패 횟수와 심야 접속 조건을 적용해 탐지 룰을 만들고, IP 조회 및 HTTP API 개념으로 확장했다.

## 학습 내용

### 비정형 로그와 정규표현식

CSV처럼 쉼표로 나뉘지 않은 로그는 `split()`만으로 필요한 정보를 안정적으로 꺼내기 어렵다. 그래서 문자 패턴을 지정하는 정규표현식을 배웠다. `\d`는 숫자, `\w`는 문자·숫자·밑줄, `+`는 1회 이상, `*`는 0회 이상, `?`는 선택적인 0~1회를 뜻한다. 대괄호 `[]`는 허용할 문자 범위를 나타내고, 소괄호 `()`는 필요한 부분을 그룹으로 묶는다.

`re.search()`는 첫 번째 일치 구간을 찾고, `re.findall()`은 일치하는 결과들을 모은다. `group()`으로 매칭 결과를 꺼내고 `(?P<user>...)`처럼 그룹에 이름을 붙이면 `groupdict()`로 항목별 딕셔너리를 만들 수 있다. 원본 문자열 앞에 붙이는 `r`은 정규표현식의 역슬래시를 다루기 편하게 한다.

### 파싱 결과를 탐지에 활용

로그에서 시간·사용자·이벤트·IP를 추출한 뒤 일정한 키로 저장하는 정규화를 진행했다. 패턴에 맞지 않는 로그는 조용히 버리는 대신 별도 파일에 남겨 확인하는 흐름이었다. 정규화된 기록을 사용하면 계정별 로그인 실패 횟수를 집계하거나 특정 시간대의 접속을 골라내는 탐지 룰을 만들 수 있다.

브루트포스 의심 조건은 반복 실패 횟수와 임계값을 비교하는 방식으로 표현했다. 실패가 아니라 **성공한 로그인이라도 새벽 시간대 같은 추가 조건이 있으면 확인할 수 있다**는 점도 배웠다. 단일 조건이 곧 공격 확정은 아니고, 경보를 발생시키는 판단 기준이라는 점을 구분했다.

### 로그 밖의 정보를 조회하기

IP만으로 알 수 없는 국가·기관 같은 정보를 외부 API에서 조회하는 흐름을 살펴봤다. 이 과정에서 GET·POST 같은 HTTP 메서드, 상태코드 `2xx`·`4xx`·`5xx`, API 키와 토큰, 인증과 인가의 차이도 함께 정리했다. 중복 IP를 제거하고 조회용 URL을 만드는 실습으로 다음 날 API 요청 학습을 연결했다.

## 실습 흐름

비정형 로그 → 정규표현식 추출 → 정규화 → 탐지 조건 → 외부 IP·API 조회

## 기억할 코드

**정규표현식으로 값 찾기**

```python
import re
line = "09:12 WARN failed login for kim01"
m = re.search(r"for (\w+)", line)
if m:
    print(m.group(1))
```

**시간 기반 탐지**

```python
row = {"time": "03:15", "level": "INFO"}
hour = int(row["time"].split(":")[0])
if hour < 6 and row["level"] == "INFO":
    print("심야 접속")
```

## 실습에서 연결된 내용

정규표현식은 기호 암기보다 **원본 로그에서 어떤 부분을 뽑아내려는지**를 먼저 정해야 이해하기 쉬웠다. 파싱과 정규화가 끝나야 탐지 조건을 일관되게 적용할 수 있고, 필요한 외부 정보는 별도의 API 요청으로 보완하는 구조였다.

## 오늘 막혔던 부분

`\w+`, `[]`, `+`, `*`, `?`가 실제로 무엇을 찾는지 반복해서 확인했다. `search()`, `findall()`, `group()`의 차이와 이름 붙인 그룹도 질문했고, `group`과 `group()`이 다르다는 점을 통해 메서드 호출 방식을 구분했다.
