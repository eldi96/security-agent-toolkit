## 3교시 · 허용 목록 IP 와 공유 IP 는 자동 차단에서 제외하고, 차단에 유효 기간(TTL)을 두어 자동 해제하기

### 문제 3-1 · 허용 목록 IP 와 공유 IP 를 판별해 차단하고, 유효 기간이 지나면 자동 해제하기

- (가) 실행한 출력 전체를 붙여 넣어 주세요. 그리고 단계 1 에서 실제로 차단된 IP 와, 차단하지 않은 IP 와 그 이유를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 실제로 차단된 IP ③ 차단하지 않은 IP 와 각 이유
  - 답: 실제로 차단된 IP는 198.51.100.90이다. 192.0.2.10은 허용 목록에 있어 차단하지 않았고, 192.0.2.41은 여러 계정이 함께 쓰는 공유 IP라 담당자 승인이 필요해 자동 차단하지 않았다.

```text
--- 단계 1: 차단 요청 3건
INC-005 198.51.100.90 · 차단되지 않음 → 차단됨 · 경로 스캔 (120분 뒤 자동 해제)
INC-009 192.0.2.10 · 변경 없음 → 변경 없음 · 허용 목록 IP 라서 차단하지 않음
INC-008 192.0.2.41 · 변경 없음 → 변경 없음 · 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
--- 단계 2: 차단 뒤 차단한 IP 와 끝나는 시각
차단한 IP: ['198.51.100.90']
차단이 끝나는 시각(분): {'198.51.100.90': 120}
--- 단계 3: 시계를 120분 뒤로 옮기고 시간이 끝난 차단 풀기
INC-005 198.51.100.90 · 차단됨 → 차단되지 않음 · 차단 시간이 끝나 자동 해제
차단한 IP: []
--- 단계 4: 파일에 저장된 값 다시 읽기
차단한 IP: []
조치 기록: 4 건
```

- (나) 🔍 INC-008 의 `192.0.2.41` 은 차단되지 않았습니다. `ip_users.json` 의 값을 근거로 차단하지 않은 이유를 적고, 그대로 차단했다면 영향을 받았을 사용자와 그 영향을 적어 주세요.
  - 쓸 내용: ① `ip_users.json` 의 값 ② 차단하지 않은 이유 ③ 그대로 차단했을 때의 영향
  - 답: ip_users.json에서 "192.0.2.41": ["junho", "hana"]로 두 계정이 등록돼 있다. 사용자 수가 SHARED_IP_LIMIT인 2 이상이라 자동 차단에서 제외했다. 그대로 차단하면 의심 요청과 무관한 정상 접속까지 포함해 junho와 hana 모두 해당 IP를 통한 서비스 접속이 막힐 수 있다.

- (다) 🔍 단계 2 의 차단이 만료 시각(120)과 단계 3 의 시계(120)를 근거로 `198.51.100.90` 이 자동 해제된 이유를 적어 주세요. 그리고 유효 기간이 있는 임시 차단이 영구 차단보다 나은 점도 적어 주세요.
  - 쓸 내용: ① 단계 2 의 만료 시각과 단계 3 의 시계 ② 풀린 이유 ③ 자동으로 풀리게 두는 것의 장점
  - 답: 단계 2의 만료 시각은 120분이고 단계 3의 모의 시계도 120분이다. expire_blocks를 호출했을 때 end_time <= state["clock"] 조건이 참이 되어 차단을 해제했다. 임시 차단은 해제를 잊어도 차단이 계속 남지 않아, 오탐이나 불필요한 장기 차단으로 정상 접속을 막는 시간을 줄일 수 있다.

## 4교시 · 계정 잠금 뒤에도 남는 활성 세션을 종료하고, 빈틈(잔존 세션)이 없는지 점검하기

  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 단계 3 에서 빈틈이 남은 계정 ③ 단계 4 의 잠긴 계정
  - 답: 단계 3에서 빈틈이 남은 계정은 []로 없고, 단계 4에 저장된 잠긴 계정은 junho와 dami이다. 조치 기록은 총 5건이다.

--- 단계 2: 잠금 → 세션 종료
INC-001 dami · 잠기지 않음 → 잠김 · 퇴사한 계정의 서버 요청

INC-003 gaeun · 변경 없음 → 변경 없음 · VIP 계정이라 자동 조치 대상이 아님

INC-006 junho · 세션 1개 → 세션 0개 · 퇴사 처리 확인

빈틈이 남은 계정: []
잠긴 계정: ['junho', 'dami']

  - 쓸 내용: ① `junho` 가 점검에서 발견된 이유 ② `dami` 가 받은 두 조치 ③ 잠금만 했을 때 남는 접속
  - 답: junho는 처음부터 잠긴 계정이지만 S-501 세션이 열려 있어 단계 1 점검에서 발견됐다. dami는 단계 2에서 계정 잠금과 세션 종료를 받아 세션이 2개에서 0개가 됐다. 잠금만 했다면 이미 로그인한 S-101과 S-102 세션이 남아 접속을 이어갈 수 있다.
