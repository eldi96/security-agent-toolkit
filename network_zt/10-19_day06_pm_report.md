## 5교시 · 왜 도커인가 · 이미지와 컨테이너 · 같이 설치하기

### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답: Docker version 29.8.2, build 7fc2dff

- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답:

    ① Docker 클라이언트: 사용자가 `docker run hello-world` 명령어를 입력하면 Docker 엔진에 실행을 요청한다.

    ② Docker 엔진: 클라이언트의 요청을 받아 `hello-world` 이미지가 있는지 확인하고, 없으면 Docker Hub에서 다운로드하도록 요청한다.

    ③ Docker Hub: Docker 엔진이 요청한 `hello-world` 이미지를 제공하고, Docker 엔진은 이미지를 다운로드한다.

    ④ 컨테이너: Docker 엔진이 다운로드한 이미지로 컨테이너를 생성하고 실행한다. 컨테이너는 `Hello from Docker!` 메시지를 출력하고 종료된다.

- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답:

    ① `docker images` (이미지): Docker Hub에서 다운로드한 `hello-world:latest` 이미지가 표시된다. 컨테이너를 생성하고 실행하기 위해 필요한 파일 묶음이다.

    ② `docker ps -a` (컨테이너): `hello-world` 이미지를 이용해 생성하고 실행한 컨테이너가 표시된다. `Hello from Docker!` 메시지를 출력한 뒤 실행이 종료되어 `Exited` 상태로 남아 있다.

    ③ 둘의 차이: 이미지는 컨테이너를 만들기 위한 실행 환경이고, 컨테이너는 그 이미지를 바탕으로 실제 실행한 것이다. 하나의 이미지로 여러 개의 컨테이너를 생성할 수 있다.

- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답:

    ```
    hello-world:latest   11a3eb1597e8   25.9kB   9.49kB   U
    ```

    ② hello-world 줄의 값과 의미

    - IMAGE: `hello-world:latest` — 이미지의 이름과 태그를 나타낸다.
    - ID: `11a3eb1597e8` — 이미지를 식별하는 고유 ID이다.
    - EXTRA: `U` — 컨테이너가 참조하고 있는 이미지임을 나타내는 사용 중 표시이다.

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답:

    ```
    CONTAINER ID   IMAGE         COMMAND    CREATED         STATUS                     PORTS   NAMES
    9956773214c4   hello-world   "/hello"   4 minutes ago   Exited (0) 4 minutes ago           fervent_cori
    ```

    ② 각 항목의 값과 의미

    - STATUS: `Exited (0) 4 minutes ago` — 컨테이너가 정상적으로 실행된 후 종료되었음을 의미한다.
    - PORTS: 빈칸 — 외부에 공개한 포트가 없음을 의미한다.
    - NAMES: `fervent_cori` — Docker가 컨테이너에 자동으로 부여한 이름이다.
    - IMAGE: `hello-world` — 해당 컨테이너를 생성할 때 사용한 이미지의 이름이다.

### 문제 5-2 · Docker Hub에서 이미지 이름 읽고 없는 이미지 받아 보기

  - 답:

    ① nginx: 사용할 이미지의 이름으로, 웹 서버 프로그램인 Nginx를 의미한다.

- (나) 🔍 `docker pull nginxx` 를 쳤을 때 나온 오류 문구와 그 뜻을 적어 주세요.

- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.

  - 답: Docker를 사용하면 개발자와 운영자가 동일한 이미지를 기반으로 프로그램과 필요한 라이브러리 및 실행 환경을 일관되게 구성할 수 있다.

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: Docker 이미지는 이름과 태그로 구분하며, Docker Hub에서 이미지를 다운로드할 때 이름이나 태그를 잘못 입력하면 오류가 발생할 수 있다는 것을 알게 되었다.


## 6교시 · nginx 서버 켜고 접속 기록 읽기

### 문제 6-1 · 포트 없이 켜 보고, 포트를 연결해 접속하고, 기록 읽기

- (가) 포트 없이 켠 `web` 에 접속했을 때 어떻게 되었는지 적어 주세요.
  - 쓸 내용: 접속했을 때 나온 화면이나 오류와 `docker ps` 의 PORTS 열
  - 답: 포트를 연결하지 않아 `localhost:8080`으로 접속했을 때 Nginx 화면에 접근할 수 없었다. `docker ps`의 PORTS 열에는 `80/tcp`만 표시되었으며, 이는 컨테이너 내부의 80번 포트가 내 PC의 포트와 연결되지 않았다는 뜻이다.

- (나) 🔍 `-p 8080:80` 이 하는 일을 내 PC의 포트와 컨테이너의 포트로 나눠 설명해 주세요.
  - 쓸 내용: ① 내 PC 쪽 포트 ② 컨테이너 쪽 포트 ③ 연결이 하는 일
  - 답: ① 내 PC의 8080번 포트를 사용한다. ② 컨테이너 내부의 80번 포트와 연결한다. ③ 내 PC의 `localhost:8080`으로 들어온 요청을 Nginx 컨테이너의 80번 포트로 전달하여 웹페이지에 접속할 수 있도록 한다.

- (다) 🔍 `docker logs web` 출력에서 `GET /` 줄 하나를 붙여 넣고, 접속자 주소 · 시각 · 요청 · 응답 번호를 찾아 적어 주세요.
  - 쓸 내용: ① `GET /` 줄 ② 접속자 주소 · 시각 · 요청 · 응답 번호 네 가지
  - 답:
    - ① GET / 로그: [실제 `docker logs web` 출력에서 `GET /`이 포함된 줄 붙여 넣기]
    - ② 접속자 주소: [로그 맨 앞의 IP 주소]
    - ③ 접속 시각: [대괄호 안의 날짜와 시간]
    - ④ 요청: `GET / HTTP/1.1`
    - ⑤ 응답 번호: [로그에 표시된 HTTP 상태 코드. 정상 응답이라면 일반적으로 200]

### 문제 6-2 · 컨테이너 안을 들여다보고, 끄고, 지우기

- (가) 컨테이너 안에서 `ls /usr/share/nginx/html` 로 본 파일 이름을 모두 적고, 그중 브라우저의 첫 화면이 어느 파일인지 적어 주세요.
  - 쓸 내용: ① 파일 이름 모두 ② 첫 화면 파일
  - 답: ① 기본 Nginx 이미지에서는 일반적으로 `50x.html`, `index.html` 파일이 보인다. ② 브라우저의 첫 화면은 `index.html` 파일이다. [실제 ls 출력과 비교 필요]

  - 답: ① `Conflict. The container name "/web" is already in use`라는 이름 중복 오류가 발생한다. [실제 오류 문구와 비교 필요] ② `docker stop`은 컨테이너를 중지할 뿐 삭제하지 않으므로 기존 이름이 남아 있다. 따라서 같은 이름으로 새 컨테이너를 만들려면 `docker rm web`으로 기존 컨테이너를 삭제해야 한다.

- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(켜는 명령 · 기록 보는 명령 · 정리 방법)
  - 답: `docker run -d --name web -p 8080:80 nginx:1.28`로 웹서버를 실행하고, `docker logs web`으로 접속 기록을 확인하며, 사용 후 `docker stop web`과 `docker rm web`으로 중지 및 삭제한다.

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 컨테이너를 실행하는 것만으로는 내 PC에서 웹서버에 접속할 수 없으며, `-p` 옵션으로 호스트와 컨테이너의 포트를 연결해야 한다는 것을 알게 되었다.

## 7교시 · 내 페이지 연결 · 두 서버 · 올리기

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답: ① 컨테이너 내부의 `index.html`을 수정한 뒤에는 변경한 웹페이지가 표시되었다. ② 컨테이너를 삭제하고 같은 이미지로 다시 생성하자 수정한 내용이 사라지고 Nginx 기본 화면으로 돌아왔다.

- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답: ① 컨테이너 내부에 직접 저장한 변경 내용은 해당 컨테이너의 저장 영역에 남기 때문에 컨테이너를 삭제하면 함께 사라진다. ② `-v`로 내 PC의 폴더를 연결하면 Nginx가 로컬 파일을 읽어 웹페이지로 제공한다. 따라서 컨테이너를 삭제해도 로컬 파일은 그대로 남으며, 로컬 파일을 수정하면 웹페이지에도 변경 내용이 반영된다.

- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답: ① [실제 오류 메시지 또는 브라우저에 표시된 화면 입력] ② Windows의 Git Bash(MSYS)가 Docker 명령어에 포함된 Linux 경로를 자동으로 Windows 형식으로 변환하면서 볼륨 연결 경로가 잘못 전달될 수 있기 때문이다. `MSYS_NO_PATHCONV=1`은 이러한 자동 경로 변환을 방지한다.

### 문제 7-2 · 서버 두 대를 띄워 포트로 구분하고, 파일을 고쳐 바로 반영되는지 보기

- (가) 두 주소(`8080` · `8081`)에서 보이는 화면을 각각 적어 주세요.
  - 쓸 내용: 두 주소의 화면 문구
  - 답:
    - `localhost:8080`: [첫 번째 서버에서 실제로 표시된 문구]
    - `localhost:8081`: [두 번째 서버에서 직접 수정한 웹페이지 문구]

- (나) 🔍 `docker ps` 의 PORTS 열에서 두 서버를 구분해 주는 것은 무엇인가요?
  - 쓸 내용: PORTS 열에서 서버를 구분하는 값
  - 답: 내 PC에 연결된 호스트 포트 번호로 구분한다. 첫 번째 서버는 `8080->80/tcp`, 두 번째 서버는 `8081->80/tcp`로 표시된다. 두 컨테이너 모두 내부에서는 80번 포트를 사용하지만, 호스트 포트가 다르므로 각각 접속할 수 있다.

- (다) 🔍 `:ro` 는 무슨 뜻이고, 왜 읽기 전용으로 연결하나요?
  - 쓸 내용: ① :ro 의 뜻 ② 읽기 전용으로 연결하는 이유
  - 답: ① `:ro`는 Read Only의 약자로 읽기 전용이라는 뜻이다. ② Nginx 컨테이너가 로컬 웹페이지 파일을 읽을 수는 있지만 수정하거나 삭제하지 못하도록 제한하기 위해 사용한다. 이를 통해 컨테이너에서 발생할 수 있는 실수나 침해로부터 로컬 파일을 보호할 수 있다.

- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(두 서버를 어떻게 띄웠는지)
  - 답: Docker에서 Nginx 컨테이너 두 개를 각각 호스트 포트 8080과 8081에 연결하여 실행하고, `-v` 옵션으로 로컬 웹페이지 폴더를 읽기 전용으로 연결해 두 서버를 독립적으로 운영했다.

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
