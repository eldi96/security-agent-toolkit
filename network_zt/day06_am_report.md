### 문제 2-1 · 새벽 대량 조회 사건 추적하고 단정할 수 있는지 따지기

- (가) 의심스러운 접근 기록은 몇 번이고, 이상해 보이지만 정상인 줄은 몇 번인가요? 한 줄씩은 정상 같지만 모아서 보면 이상한 줄이 있으면 함께 적어 주세요.
  - 쓸 내용: 「의심: 번호 … / 이상해 보이지만 정상: 번호 … (정상으로 본 이유) / 모으면 이상한 줄: 번호 … (이유)」
 - **의심: 2, 3, 4, 5번** — 새벽 02:14에 seoyeon 계정이 평소 업무 시간과 다른 장비(NB-7741) 와 IP(10.20.5.77)에서 비밀번호만으로 로그인한 뒤, 1분 이내에 SETTLE 데이터를 3회 조회했다.
    - **이상해 보이지만 정상: 1번** — 새벽 02:00에 SETTLE 데이터 320건을 조회했지만, batch-night 계정과 SRV-BATCH 장비를 사용한 정기 배치 작업으로 보인다. 다만 실제 작업 일정과 등록 정보를 확인해야 정상이라고 확정할 수 있다.
    - **모으면 이상한 줄: 3, 4, 5번** — 각각 40건의 조회는 정상적인 요청처럼 보이지만, 1분 이내에 같은 데이터를 3회 연속 조회하여 총 120건의 조회 요청이 발생했다. 반복 조회의 목적을 확인해야 한다.

- (나) 🔍 의심스러운 줄의 근거 필드는 무엇인가요? 필드마다 등록 정보나 같은 계정의 다른 줄과 어떻게 다른지 적어 주세요.
  - 쓸 내용: 근거 필드 세 가지 이상, 필드마다 「어떤 값이 어떤 값과 다른지」
  - 답: 1. **접속 시간:** 2번은 새벽 02:14에 로그인했지만, 같은 계정의 8번은 오전 10:40에 로그인했다. 일반적인 업무 시간과 차이가 있다.
    2. **접속 장비:** 2~5번은 NB-7741을 사용했지만, 8~18번은 NB-0417을 사용했다.
    3. **IP 주소:** 2~5번은 10.20.5.77이지만, 8~18번은 10.20.4.21이다.
    4. **인증 방식:** 2번은 비밀번호만 사용하는 success(pw)이지만, 8번은 다중 인증을 거친 success(pw+mfa)이다.
    5. **조회 패턴:** 3~5번은 1분 이내에 SETTLE 데이터를 40건씩 3회 조회했다. 반면 주간 기록은 조회 간격이 상대적으로 길다. 다만 주간에도 반복 조회가 있으므로 횟수만으로 공격이라고 판단할 수는 없다.

- (다) 🔍 방화벽이 막지 못하고 통과한 이유를 5대 원칙의 어느 칸이 비어 있었는지로 설명해 주세요.
  - 쓸 내용: ① 비어 있던 칸 두 개 이상 ② 칸마다 확인했어야 할 것
  - 답:  
    1. **사용자 인증 확인:** 비밀번호만으로 로그인한 계정이 정상 사용자 본인인지 추가 인증(MFA)을 통해 확인했어야 한다.
    2. **접속 장비 확인:** NB-7741이 seoyeon 계정에 등록되거나 승인된 장비인지 확인했어야 한다.
    3. **접속 시간 및 행위 확인:** 새벽 시간의 로그인과 짧은 시간에 반복되는 SETTLE 조회가 정상 업무에 해당하는지 확인했어야 한다.

    방화벽은 허용된 IP, 포트, 통신 규칙에 따라 접근을 통과시킬 수 있지만, 계정의 실제 사용자나 조회 행위의 정상 여부까지 반드시 판단하는 것은 아니다. 따라서 방화벽 규칙만으로는 부족하며 인증 정책, 장비 검증, 행위 탐지 등의 추가 통제가 필요하다.

- (라) 🔍 이 기록만으로 「seoyeon 계정이 도용됐다」고 단정할 수 있나요? 기록으로 확인된 것과 확인하지 못한 것, 그것을 확인하려면 볼 자료를 적어 주세요.
  - 쓸 내용: ① 단정할 수 있는지 ② 기록으로 확인된 것 ③ 확인하지 못한 것 ④ 확인하려면 볼 자료
  - 답:    1. **단정할 수 없다.** 의심스러운 정황은 있지만 실제 계정 도용의 증거는 부족하다.
    2. **확인된 것:** 새벽 02:14에 seoyeon 계정으로 비밀번호 인증에 성공했고, NB-7741 장비와 10.20.5.77 IP에서 SETTLE 데이터를 3회 조회했다. 해당 접근은 모두 허용되었다.
    3. **확인하지 못한 것:** 실제 접속자가 seoyeon 본인인지, NB-7741이 승인된 장비인지, 새벽 작업이 정상 업무인지, 조회한 데이터가 외부로 유출되었는지는 알 수 없다.
    4. **추가 확인 자료:** 사용자와 장비 등록 정보, MFA 인증 로그, VPN 및 접속 이력, 데이터베이스 감사 로그, 해당 시간의 업무 승인 기록을 확인해야 한다.

- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(무슨 일이 있었고 무엇을 더 확인해야 하는지)
  - 답: seoyeon 계정이 새벽 02:14에 평소와 다른 장비와 IP에서 비밀번호만으로 로그인한 후 SETTLE 데이터를 반복 조회한 기록이 확인되어, 계정 도용 여부를 판단하기 위해 장비 등록 정보와 MFA 인증 로그 및 DB 접근 기록을 추가 확인해야 합니다.

### 문제 2-2 · 접속 요청 여섯 개를 5대 원칙의 칸으로 분류하기

- (가) 요청 ① ~ ⑥ 은 각각 5대 원칙 중 어느 칸에서 걸리나요? 걸리지 않고 통과하면 「통과」라고 적어 주세요.
  - 쓸 내용: 「①: … / ②: … / ③: … / ④: … / ⑤: … / ⑥: …」 여섯 개
  - 답:  
    - ①: ID
    - ②: Device
    - ③: Application
    - ④: Network
    - ⑤: Policy
    - ⑥: 통과

- (나) 🔍 요청 ⑤ 는 ID · Device · Application 이 모두 정상인데 왜 Policy 칸에서 걸리나요?
  - 쓸 내용: ① 정상인 것 ② 평소와 달라진 상황 ③ Policy 칸이 하는 일
  - 답:⑤는 비밀번호와 MFA 인증을 완료했고(ID), 회사 노트북도 최신 상태이며(Device), 영업 앱에 접근할 권한도 있다(Application). 하지만 평소 서울에서 접속하던 사용자가 새벽 03:00에 해외 IP로 접속했다는 점이 다르다. Policy는 사용자 인증과 접근 권한이 정상이어도 접속 시간, 위치, 평소 행동 등을 종합적으로 확인하여 위험한 접근을 차단하거나 추가 인증을 요구하는 역할을 한다.

- (다) 요청 ③ 과 ④ 는 둘 다 가면 안 되는 곳에 닿으려는 시도인데 왜 서로 다른 칸에서 걸리나요?
  - 쓸 내용: ① ③ 이 확인하는 것 ② ④ 가 확인하는 것
  - 답:③은 마케팅팀 사용자가 접근 권한이 없는 인사 시스템 앱에 접속하려는 것이므로 Application에서 걸린다. 반면 ④는 서버 구역의 DB에 허용된 애플리케이션을 거치지 않고 직접 연결하려는 것이므로 Network에서 걸린다. 즉, Application은 해당 서비스에 접근할 권한이 있는지 확인하고, Network는 허용된 네트워크 경로로 접속하는지 확인한다.

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답:Zero Trust는 로그인에 성공했다고 모든 접근을 허용하는 것이 아니라, ID → Device → Network → Application → Policy 순서로 사용자 인증, 기기 상태, 네트워크 경로, 애플리케이션 접근 권한, 접속 상황을 확인한다는 것을 알게 되었다.

## 3교시 · 점수로 판단하는 함수 (PDP)
### 문제 3-1 · 권한 변경 판단 함수의 점수 직접 정하기

- (가) 내가 채운 코드 여덟 줄을 붙여 넣어 주세요.
  - 쓸 내용: `# ←` 여덟 곳에 채운 코드(점수 세 개 · 역할 검사 두 줄 · MFA 점수 블록 세 줄)
  - 답:

```python
HEALTH_POINTS = 50
MFA_POINTS = 30
COUNTRY_POINTS = 20

if account["role"] != "account_admin":
    return "거부", ["관리자 역할이 아님"]

if req["mfa"] == False:
    score = score + MFA_POINTS
    reasons.append("MFA 안 함")
```

- (나) 🔍 실행해서 나온 요청 A ~ F 의 결정을 적어 주세요. 모두 기대 결정과 같은지도 함께 적어 주세요.
  - 쓸 내용: 「A: … / B: … / C: … / D: … / E: … / F: …」 여섯 개와 「기대 결정과 같음 · 다름」
  - 답:
    - A: 허용 (위험 점수 0점)
    - B: 거부 (관리자 역할이 아님)
    - C: 추가확인 (MFA 미사용, 30점)
    - D: 거부 (기기 보안 상태 이상, 50점)
    - E: 추가확인 (해외 접속, 20점)
    - F: 거부 (MFA 미사용 30점 + 해외 접속 20점 = 50점)

    모든 요청이 의도한 기대 결정과 같다.

- (다) 🔍 점수 세 개를 정하면서 찾은 조건을 적어 주세요. 점수 하나가 가질 수 있는 범위와, 두 점수의 합이 만족해야 하는 조건이 있나요?
  - 쓸 내용: ① 기기 보안 상태 이상 점수의 범위 ② MFA 점수와 해외 점수의 범위 ③ 둘의 합이 만족해야 하는 조건과 그 이유(요청 몇 번 때문인지)
  - 답:
    1. **기기 보안 상태 이상 점수:** 요청 D가 거부되어야 하므로 50점 이상이어야 한다.
    2. **MFA 미사용 점수와 해외 접속 점수:** 요청 C와 E가 각각 추가확인이 되어야 하므로 두 점수 모두 10점 이상 50점 미만이어야 한다.
    3. **두 점수의 합:** 요청 F는 MFA 미사용과 해외 접속이 동시에 발생하므로 두 점수의 합이 50점 이상이어야 거부된다.

    따라서 HEALTH_POINTS = 50, MFA_POINTS = 30, COUNTRY_POINTS = 20으로 정했다.

- (라) 🔍 기기 보안 상태 이상은 정산 조회에서는 추가확인인데 권한 변경에서는 거부입니다. 왜 기준이 다른가요?
  - 쓸 내용: ① 정산 조회에서 그 신호의 점수와 결정 ② 내가 정한 권한 변경 점수와 결정 ③ 기준이 다른 이유
  - 답:
    1. **정산 조회:** 기기 보안 상태 이상이 발생하면 추가확인을 요구한다. (정산 조회 문제에서 설정한 점수는 별도로 확인해야 한다.)
    2. **권한 변경:** 기기 보안 상태 이상에 50점을 부여했으므로 즉시 거부한다.
    3. **기준이 다른 이유:** 정산 조회는 기존 데이터를 확인하는 작업이지만, 권한 변경은 사용자의 접근 권한을 바꾸는 민감한 작업이다. 권한이 잘못 변경되면 다른 시스템이나 데이터에 무단 접근할 수 있으므로 더 엄격한 보안 기준을 적용해야 한다.

### 문제 3-2 · 요청 7건을 한꺼번에 판정해 건수 세기

- (가) 실행해서 나온 출력 전체를 붙여 넣어 주세요.
  - 쓸 내용: 거부 · 추가확인 줄, 건수 줄, 이유별 건수 줄 전체
  - 답:
      [추가확인] 2 seoyeon ['대량 조회 (+30)']
      [거부] 3 seoyeon ['이 계정에 등록된 기기가 아님']
      [거부] 4 dami ['재직 중인 계정이 아님']
      [추가확인] 5 junho ['기기 보안 상태 이상 (+40)']
      [거부] 6 junho ['해외에서 접속 (+30)', '새벽 접속 (+20)']
      [거부] 7 seoyeon ['이 계정에 등록된 기기가 아님']
      허용 1 건 / 추가확인 2 건 / 거부 4 건
      거부 이유별 건수 {'이 계정에 등록된 기기가 아님': 2, '재직 중인 계정이 아님': 1, '해외에서 접속 (+30)': 1, '새벽 접속 (+20)': 1}

- (나) 🔍 거부된 요청 중 필수 조건에서 바로 거부된 것과 점수가 쌓여서 거부된 것은 각각 몇 번 요청이고 이유가 무엇인가요?
  - 쓸 내용: ① 필수 조건으로 거부된 요청 번호와 이유 ② 점수로 거부된 요청 번호와 이유 목록
  - 답: 필수 조건으로 거부된 요청은 3번과 7번(등록되지 않은 기기 NB-7741), 4번(퇴사한 계정 dami)이다. 점수로 거부된 요청은 6번이며, 해외 접속(+30)과 새벽 접속(+20)이 합쳐져 50점으로 거부되었다.

- (다) 🔍 거부 이유별 건수에서 가장 많은 이유는 무엇이고, 이 숫자는 보안 담당에게 무엇을 알려 주나요?
