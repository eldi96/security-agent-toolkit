# 2과목 회고 (10/21(수))

## 잘 이해한 것

- **네트워크 기본 원리:** IP, 포트, DNS, ARP, TTL, ping의 역할을 배우고, 연결이 실패했을 때 어느 부분에 문제가 있는지 구분하는 방법을 익혔다.
- **서버와 통신:** Python으로 간단한 서버를 만들고 GET·POST 요청과 HTTP 상태 코드(200, 404, 405, 500 등)를 직접 확인하면서 클라이언트와 서버의 통신 흐름을 이해했다.
- **Docker와 네트워크:** 이미지와 컨테이너의 차이, 포트 바인딩, `127.0.0.1`과 `0.0.0.0`의 차이를 실습했다. 특히 컨테이너가 `Up` 상태여도 포트 설정이 잘못되면 접속할 수 있다는 것이 아니라, 접속에 실패할 수 있다는 점을 이해했다.
- **보안 로그 분석:** 접근 기록의 시각·계정·기기·거부 이유를 비교해 이상 행동을 찾고, 로그에서 확인된 사실과 추정한 원인을 구분하는 방법을 배웠다.
- **접근통제와 대응:** Zero Trust, MFA, 최소권한 원칙을 배우고, 무조건 차단하기보다 위험과 정상 사용자의 불편을 함께 고려해야 한다는 점을 이해했다.

## 막힌 것

- Docker의 내부 IP와 WSL의 가상 네트워크가 왜 필요한지, 컨테이너 이름으로 접속할 수 있는 조건이 무엇인지 이해하는 데 시간이 걸렸다.
- 포트 바인딩과 바인드 마운트처럼 비슷한 용어를 구분하고, 호스트와 컨테이너의 연결 관계를 이해하는 것이 어려웠다.
- Python 로그 분석에서 `last = {}`처럼 비어 있는 딕셔너리에 반복문을 통해 값이 저장되는 과정과 `if user in last` 조건이 필요한 이유가 처음에는 헷갈렸다.
- 보안 로그에서 의심스러운 행동을 발견하더라도 실제 공격인지 정상적인 재시도인지 단정할 수 없어, 추가로 어떤 기록을 확인해야 하는지 판단하는 것이 어려웠다.

## 3과목과 캡스톤에서 이어 갈 것

- Python으로 작성한 로그 분석 코드를 확장해 반복된 접근 실패, 미등록 기기, MFA 미완료 등의 조건을 자동으로 탐지하고 싶다.
- Zero Trust와 최소권한 원칙을 바탕으로 접근 요청을 허용·추가 확인·거부로 분류하는 접근통제 자동화를 구현하고 싶다.
- Docker를 활용해 실제 서비스 환경을 구성하고, 네트워크 연결 문제와 보안 위협을 구분해 대응하는 실습을 이어 가고 싶다.
- 단순히 이상 행동을 탐지하는 데서 끝나지 않고, **탐지 근거를 설명하고 위험도에 따라 대응 수준을 조정하는 시스템**으로 발전시키고 싶다.
