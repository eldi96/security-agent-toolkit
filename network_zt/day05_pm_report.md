### 문제 5-1 · 지연 · 지터 · 손실을 직접 계산하기

- (가) 회선 X 와 Y 의 평균 지연과 지터(이웃한 두 값의 차이의 평균), 회선 Z 의 손실률을 각각 구해 적어 주세요.
  - 쓸 내용: 「X: 평균 … ms · 지터 … ms / Y: 평균 … ms · 지터 … ms / Z: 손실 … %」

- (나) 🔍 평균 지연만 보면 Y 가 더 좋아 보입니다. 화상회의에는 어느 회선이 더 나쁠까요? 왜 그런가요?
  - 쓸 내용: ① 회선 이름 하나 ② 지연 · 지터 숫자를 써서 이유
  - 답: Y 회선이다. 평균 지연은 26 ms로 X의 30 ms보다 낮지만, 지터가 38 ms로 X의 1 ms보다 훨씬 높아 응답 시간이 불규칙하기 때문이다. 따라서 실시간 통신인 화상회의에서는 영상과 음성이 끊기거나 지연될 가능성이 더 크다.

## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:
```python
def jitter(got):
    """
    하는 일: 연속된 ping 응답 시간의 차이를 이용해 평균 지터를 계산한다.
    입력: got - 응답을 받은 ping 시간 목록(ms)
    리턴: 평균 지터(ms)
    """
    total = 0
    for i in range(1, len(got)):
        total += abs(got[i] - got[i - 1])
    return total / (len(got) - 1)
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답:
```text
회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
회선 B | 지연 42.3 ms | 지터 52.8 ms | 손실 0 %
회선 C | 지연 41.0 ms | 지터 1.5 ms | 손실 30 %
```

- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: `jitter` 함수는 연속된 ping 응답 시간 차이의 절댓값을 평균 낸 지터(ms)를 리턴한다. `measure` 함수의 `jitter_value = jitter(got)`에서 반환값을 받아 `jitter_value`에 저장하고, `print()`에서 소수점 첫째 자리까지 출력한다.

### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (가) 세 회선의 판정 결과(적합 · 부적합)와 걸린 기준을 각각 적어 주세요.
  - 쓸 내용: 「A: … / B: … (걸린 기준 …) / C: … (걸린 기준 …)」
  - 답: A: 적합 / B: 부적합 (걸린 기준: 지터 약 52.8ms로 30ms 초과) / C: 부적합 (걸린 기준: 손실률 30%로 1% 초과)

- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: 회선 C의 손실률은 30%로 허용 기준인 1%를 초과하기 때문에 부적합하다. 패킷 손실이 발생하면 화상회의 중 음성이 끊기거나 영상이 멈추는 문제가 생길 수 있다.

- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: `and`는 지연, 지터, 손실률이 모두 기준을 만족해야 적합으로 판정하기 위해 사용한다. `or`로 바꾸면 세 조건 중 하나만 만족해도 적합으로 판정하므로, 지터가 기준을 초과한 회선 B도 적합으로 잘못 판정된다.

- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)
  - 답: 화상회의에는 회선 A가 적합하며, 회선 B는 지터가 높고 회선 C는 패킷 손실률이 높아 부적합합니다.

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 네트워크 품질은 응답 속도인 지연뿐 아니라 응답 시간의 변동을 나타내는 지터와 패킷 손실률까지 함께 확인해야 정확하게 판단할 수 있다는 것을 알게 되었다.

## 7교시 · tracert · 진단 · 올리기

### 문제 7-1 · tracert 표에서 느려진 구간 찾기

- (가-1) 표 1 에서 지연이 처음 크게 뛴 구간은 몇 번 홉과 몇 번 홉 사이인가요?
  - 쓸 내용: 「… 번 홉과 … 번 홉 사이」 하나
  - 답: 4번 홉과 5번 홉 사이

- (가-2) 그 구간은 우리 회사 쪽일까요, 바깥(통신사)일까요? 근거를 적어 주세요.
  - 쓸 내용: ① 「사내 / 바깥」 하나 ② 근거(사내 홉의 시간 또는 장비 이름)
  - 답: 바깥(통신사) 구간이다. 사내 공유기와 방화벽은 각각 1ms, 2ms로 지연이 작고, 통신사 중계 장비인 4번 홉(6ms)에서 해외 연결 지점인 5번 홉(48ms)으로 넘어가면서 지연이 크게 증가했기 때문이다.

- (나) 🔍 표 2 의 4번 홉은 60 ms 로 큰데 실제 장애가 아니라고 봅니다. 그 근거는 무엇인가요?
  - 쓸 내용: ① 4번 홉의 뒤 홉 시간 ② 그것이 무엇을 뜻하는지
  - 답: 4번 홉은 60ms이지만 뒤의 5번 홉은 7ms, 6번 홉은 8ms로 다시 낮아진다. 이는 4번 장비가 tracert 응답을 늦게 보냈을 가능성이 있으며, 실제 통신 경로 전체에 지연이 발생한 것은 아닐 수 있다는 뜻이다.

### 문제 7-2 · SaaS 접속이 느린 고객 진단하기

- (가) 이 고객의 SaaS 접속이 느린 원인 구간은 어디인가요?
  - 쓸 내용: 「… 번 홉과 … 번 홉 사이」 + 어떤 장비 구간인지
  - 답: 4번 홉과 5번 홉 사이이다. 통신사 중계 장비에서 해외 연결 지점으로 넘어가는 구간으로, 지연 시간이 6ms에서 48ms로 크게 증가했다.

- (나) 🔍 그 구간은 우리가 고칠 수 있나요? 고칠 수 없다면 고객에게 무엇을 말하고 무엇을 요청하나요?
  - 쓸 내용: ① 「고칠 수 있다 / 없다」 ② 고객에게 할 말 한 문장 ③ 요청할 곳과 붙일 자료
  - 답: 직접 고칠 수 없다. 고객에게 "사내 네트워크에서는 큰 지연이 확인되지 않았으며, 통신사 해외 연결 구간에서 지연이 증가하는 것으로 보입니다."라고 안내한다. 통신사에 경로 점검을 요청하고, tracert 측정 결과와 측정 시각, 목적지 정보를 함께 전달한다.

- (다) 이 측정은 한 시각의 값입니다. 이 값만으로 원인을 단정할 수 없는 이유와, 추가로 잴 것 한 가지를 적어 주세요.
  - 쓸 내용: ① 단정할 수 없는 이유 한 가지(한 시각의 값) ② 추가로 잴 것 한 가지
  - 답: 한 시각에 측정한 결과이므로 일시적인 네트워크 혼잡이나 장비의 응답 지연일 가능성이 있어 원인을 단정할 수 없다. 시간대를 달리하여 tracert를 반복 측정하고 같은 구간에서 지연이 지속적으로 발생하는지 확인해야 한다.

- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(우리 구간 상태, 원인 구간, 요청할 곳)
  - 답: 사내 네트워크 구간은 정상으로 보이며, 통신사 중계 장비와 해외 연결 지점 사이에서 지연이 증가해 통신사에 경로 점검을 요청하겠습니다.

- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: tracert를 이용하면 목적지까지 거치는 장비와 각 홉의 응답 시간을 확인할 수 있으며, 지연이 발생하는 구간을 추정할 수 있지만 한 번의 측정만으로 장애 원인을 확정할 수는 없다는 것을 알게 되었다.

- SaaS 접속이 느린 원인 구간과 그 근거를 적어 주세요.
  - 쓸 내용: ① 원인 구간 ② 근거(tracert 에서 뛴 값) ③ 사내 구간이 정상이라는 근거
  - 답: 지연이 증가한 구간은 4번 홉(통신사 중계 장비)과 5번 홉(해외 연결 지점) 사이이다. tracert 결과에서 응답 시간이 6ms에서 48ms로 크게 증가했기 때문이다. 반면 사내 공유기는 1ms, 사내 방화벽은 2ms로 큰 지연이 확인되지 않아 사내 구간보다는 외부 통신사 구간에서 지연이 증가한 것으로 추정된다.

### 4. 한계와 다음 확인

- 이 진단으로 알 수 없는 것 하나와, 다음에 확인할 것 하나를 적어 주세요.
  - 쓸 내용: ① 알 수 없는 것(예: 한 시각의 값이라는 점) ② 다음 확인(시간대를 바꿔 다시 재기 · 구간 운영자에게 확인 요청)
  - 답: 한 시각에 측정한 tracert 결과만으로는 지연이 일시적인 현상인지 지속적인 문제인지 알 수 없다. 따라서 시간대를 바꿔 반복 측정하고, 같은 구간에서 지연이 계속 발생한다면 통신사에 측정 결과를 전달하여 확인을 요청해야 한다.
