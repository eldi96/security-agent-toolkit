# 정산 포털 정책 로그 점검 결과
## 결론
- 정책 로그 12건과 앱 접근 기록 13건을 비교한 결과, 총 4건의 이상이 확인되었다. 접근 통제 오류를 우선 조사하고, 정상 업무에 대한 불필요한 차단을 줄이기 위해 탐지 기준을 조정할 필요가 있다.
## 근거
- 정책 집행 이상 4건: 요청 101·108은 집행 누락(보안 정책에서 요구한 제한을 앱이 제대로 적용하지 않은 경우), 요청 112는 과집행(정책보다 강하게 접근을 제한한 경우), 요청 201은 우회 의심(정책 결정 기록 없이 앱에서 처리된 경우)으로 확인되었다.

- 현재 탐지 규칙: 대량 조회 기준 20건을 적용하면 정상 요청 9건 중 6건이 오탐(정상 요청을 위험하다고 잘못 판단한 경우)으로 분류된다. 위험 요청 2건의 미탐(위험 요청을 거부하지 못한 경우)은 0건이다.

- 조정안 비교: A안은 오탐 0건·미탐 1건이며, B안과 C안은 각각 오탐 0건·미탐 2건이다. A안에서는 해외에서 49건을 조회한 요청 11번이 거부되지 않고 추가확인으로 판정된다.

## 권고
- 접근 통제 점검: 요청 101·108·201을 우선 조사하고, PEP(정책 결정에 따라 실제 접근을 허용하거나 차단하는 구성 요소)의 설정과 정책 전달 기록을 확인한다. 요청 201은 실제 우회인지 로그 누락인지 추가 확인한다.

- A안 적용 검토: 대량 조회 기준을 20건에서 50건으로 높이는 A안을 우선 검토한다. 오탐은 6건에서 0건으로 감소하지만, 해외에서 49건을 조회한 위험 요청 11번을 새로 놓치므로 해외 접속과 조회 패턴을 함께 확인하는 보완 규칙이 필요하다.
