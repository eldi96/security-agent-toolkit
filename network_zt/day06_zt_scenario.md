# A사 Zero Trust 적용 방안

## 5대 원칙 적용 방안

- **ID:** 모든 로그인 경로에 MFA를 적용하여 비밀번호만으로 로그인하지 못하도록 한다.
- **Device:** 회사에 등록된 기기만 접근하도록 제한하고, 백신 및 보안 업데이트 상태를 점검한다.
- **Network:** 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다.
- **Application:** 부서별 업무에 필요한 시스템만 접근할 수 있도록 권한을 제한한다. 정산 내역은 재무팀만 조회할 수 있도록 한다.
- **Policy:** 접속 시간, 국가, 기기 상태, MFA 여부, 조회 건수를 바탕으로 위험 점수를 계산하여 허용·추가확인·거부를 결정한다.

## 판단과 집행

- **PDP(결정):** 사용자 요청의 필수 조건과 위험 점수를 검사하여 허용·추가확인·거부를 결정한다.
- **PEP(집행):** 정산 포털 앞의 프록시에서 PDP의 결정에 따라 요청을 통과시키거나 추가 인증을 요구하고, 위험한 접근은 차단하여 로그에 기록한다.

## 흐름도

```text
사용자 --요청--> PEP --문의--> PDP
                  ^           |
                  |           | 1. 필수 조건 검사
                  |           |    - 재직 중인 계정인가?
                  |           |    - 등록된 기기인가?
                  |           |
                  |           | 2. 위험 점수 계산
                  |           |    - 기기 상태, 국가, 시간
                  |           |    - MFA 여부, 조회 건수
                  |           |
                  |           | 3. 최종 결정
                  |           |    - 50점 이상: 거부
                  |           |    - 20~49점: 추가확인
                  |           |    - 20점 미만: 허용
                  |           |
                  +--결정-----+

PEP 집행
- 허용     → 애플리케이션 접근 허용
- 추가확인 → MFA 등 추가 인증 요구
- 거부     → 접근 차단 및 로그 기록
```

## 최소권한 기준 (목록에 없으면 거부)

- **재무팀:** 정산 내역(SETTLE) 조회만 허용한다.
- **영업팀:** 영업 실적(SALES) 조회만 허용한다.
- **서비스 계정 batch-night:** 매일 02:00 정산 집계 작업을 위한 SETTLE 접근만 허용한다.

허용 목록에 없는 시스템이나 기능에 대한 접근은 기본적으로 거부한다.

## 스코어링 결과

- **항목별 점수:**
  - MFA: 10점 / 20점
  - 기기 보안: 5점 / 20점
  - 최소권한: 15점 / 20점
  - 세그멘테이션: 0점 / 20점
  - 위험 기반 인증: 0점 / 20점

- **총점:** 30점 / 100점

- **먼저 올릴 항목과 이유:**

  기기 보안(Device)을 우선 개선한다.

  직원 12명 중 기기 보안 점검을 통과한 직원은 3명으로, 기기 점검 비율이 25%에 불과하다.

  또한 최근 새벽에 `seoyeon` 계정이 등록되지 않은 기기에서 정산 내역 120건을 조회했지만 차단되지 않은 사고가 있었다.

  따라서 등록된 기기만 접근할 수 있도록 제한하고, 기기 보안 상태를 확인하는 정책을 우선 적용해야 한다.
