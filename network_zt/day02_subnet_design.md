### 문제 2-1 · 내 IP를 2진수로

#### (가) `warmup_2_1b.py` 실행 결과

내 IPv4 주소: `192.168.10.25`

```text
192 11000000
168 10101000
10 00001010
25 00011001
```

#### (나-1) `format(number, "08b")`가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.

**답:**

`format(number, "08b")`는 10진수를 **8자리의 2진수 문자열**로 변환하는 함수이다.

예를 들어 `192`를 변환하면 `11000000`이 출력된다.

2진수의 각 자리는 왼쪽부터 `128, 64, 32, 16, 8, 4, 2, 1`의 값을 가진다.

`11000000`에서 왼쪽 두 자리는 `1`이고 나머지는 `0`이다. `1`은 해당 자리의 값을 사용한다는 의미이고, `0`은 사용하지 않는다는 의미이다.

따라서 `128 + 64 = 192`이므로, 10진수 `192`를 2진수로 표현하면 `11000000`이 된다.

#### (나-2) `"08b"`에서 `08`을 빼고 `"b"`만 쓰면 `10`은 어떻게 출력되나요?

**답:**

```text
192 11000000
168 10101000
10 1010
25 11001
```

`format(10, "b")`를 사용하면 `1010`이 출력된다.

`"b"`는 숫자를 2진수로 변환하지만 자릿수를 고정하지 않는다. 따라서 앞에 불필요한 `0`이 붙지 않는다.

반면 `"08b"`는 2진수로 변환한 결과가 8자리보다 짧으면 왼쪽을 `0`으로 채워 최소 8자리로 표현한다.

- `format(10, "b")` → `1010`
- `format(10, "08b")` → `00001010`

#### (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.

**답:**

IPv4 주소는 총 **32비트**로 구성되며, 이를 8비트씩 4개의 옥텟(마디)으로 나누기 때문이다.

각 옥텟은 8비트로 구성되므로 2진수로 표현할 때 앞에 `0`을 채워 8자리를 맞춰야 한다.

이렇게 하면 각 옥텟의 경계를 명확하게 구분하고, IPv4 주소 전체를 정확히 32비트로 표현할 수 있다.

#### (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.

**답:**

IPv4 주소는 총 32비트이며, 점(`.`)을 기준으로 **4개의 옥텟(마디)**으로 나뉜다.

32비트를 4개의 옥텟으로 나누면 `32 ÷ 4 = 8비트`이므로, 각 옥텟은 8비트로 구성된다.

1비트는 `0` 또는 `1`의 두 가지 값을 가질 수 있으므로, 8비트로 표현할 수 있는 경우의 수는 `2⁸ = 256가지`이다.

가장 작은 값은 `00000000`으로 10진수 `0`이고, 가장 큰 값은 `11111111`로 10진수 `255`이다.

따라서 IPv4 주소의 각 옥텟은 **0부터 255까지의 값**을 가질 수 있다.

#### (다-2) 32비트로 만들 수 있는 주소의 개수

**답:**

`2³² = 4,294,967,296개 (약 43억 개)`

#### (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.

**답:**

1. **1비트의 경우:** `0` 또는 `1`이 들어갈 수 있으므로 2가지이다.
2. **2비트의 경우:** `00`, `01`, `10`, `11`로 총 `2 × 2 = 4가지`이다.
3. **3비트의 경우:** `2 × 2 × 2 = 8가지`이다.
4. **32비트의 경우:** 각 자리마다 2가지 값을 선택할 수 있으므로 2를 32번 곱한다.

따라서 `2³² = 4,294,967,296`으로, IPv4는 이론적으로 약 43억 개의 서로 다른 주소를 표현할 수 있다.

#### (다-4) 이 수의 한계가 사설 IP와 NAT를 쓰게 된 것과 어떻게 이어지는지 설명하세요.

**답:**

IPv4는 약 43억 개의 주소만 표현할 수 있다.

인터넷이 발전하면서 컴퓨터, 스마트폰, 서버 등 인터넷에 연결되는 장치가 급격히 증가했고, 모든 장치에 고유한 공인 IPv4 주소를 할당하기 어려워졌다.

이러한 주소 부족 문제를 완화하기 위해 **사설 IP와 NAT**를 활용한다.

1. **사설 IP:** 가정이나 회사의 내부 네트워크에서 사용하는 IP 주소이다. 서로 다른 내부 네트워크에서는 같은 사설 IP를 중복해서 사용할 수 있다.
2. **NAT(Network Address Translation):** 공유기나 라우터 등이 내부 장치의 사설 IP를 공인 IP로 변환하여 인터넷과 통신할 수 있도록 하는 기술이다.
3. **공인 IP 절약:** NAT의 한 종류인 NAPT를 이용하면 여러 장치가 하나의 공인 IP를 공유할 수 있으므로, 장치마다 별도의 공인 IP를 할당할 필요가 줄어든다.

예를 들어 집에 컴퓨터 2대와 스마트폰 3대가 있어도, 각 장치에 사설 IP를 할당하고 공유기의 NAPT 기능을 사용하면 5대의 장치가 하나의 공인 IP를 공유하여 인터넷을 사용할 수 있다.

결과적으로 **사설 IP의 재사용과 NAT를 통한 공인 IP 공유는 IPv4 주소 부족 문제를 완화하는 데 중요한 역할**을 한다.

#### (나-1) 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.

**답:**

내 IPv4 주소는 `192.168.100.174`이며, 전통적인 C 클래스에 해당하는 사설 IP 범위에 포함된다.

- 사설 IP 시작 주소: `192.168.0.0`
- 사설 IP 끝 주소: `192.168.255.255`
- 내 IPv4 주소: `192.168.100.174`

내 IPv4 주소는 `192.168.0.0` 이상이고 `192.168.255.255` 이하이므로 해당 범위에 포함된다.

따라서 **내 IPv4 주소는 공인 IP가 아닌 사설 IP**이다.

#### (나-2) `curl`로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.

**답:**

`curl`로 확인한 IPv4 주소는 `1.245.252.171`이며, 공인 IP에 해당한다.

2.2 표의 사설 IP 범위 세 가지와 비교하면 다음과 같다.

| 구분 | 사설 IP 범위 | 해당 여부 |
|---|---|---|
| A 클래스 대역 | `10.0.0.0 ~ 10.255.255.255` | 해당하지 않음 |
| B 클래스 대역 | `172.16.0.0 ~ 172.31.255.255` | 해당하지 않음 |
| C 클래스 대역 | `192.168.0.0 ~ 192.168.255.255` | 해당하지 않음 |

`1.245.252.171`은 위 세 가지 사설 IP 범위에 포함되지 않으며, 다른 특수 목적 예약 주소 범위에도 해당하지 않는다.

따라서 **`curl`로 확인한 `1.245.252.171`은 공인 IPv4 주소**이다.

#### (나-3) 관제 로그의 출발지 주소가 `172.20.5.6`과 `172.32.5.6`이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.

**답:**

**1. `172.20.5.6` → 사설 IP (내부망 장비로 우선 분류)**

- 사설 IP 범위: `172.16.0.0 ~ 172.31.255.255`
- `172.20.5.6`은 해당 범위에 포함되므로 사설 IP이다.

**2. `172.32.5.6` → 공인 IP (외부 주소로 우선 분류)**

- 사설 IP 범위: `172.16.0.0 ~ 172.31.255.255`
- `172.32.5.6`은 사설 IP 범위의 끝 주소인 `172.31.255.255`를 초과하므로 공인 IP에 해당한다.

따라서 `172.20.5.6`은 내부망 장비의 주소로, `172.32.5.6`은 외부 주소로 우선 분류할 수 있다.

단, 실제 관제에서는 IP 주소의 종류만으로 통신 주체의 위치를 확정할 수 없으므로 네트워크 구성과 NAT 기록 등을 함께 확인해야 한다.

#### (다-1) 외부 서버 로그에 남은 출발지 IP만으로는 내부망의 어느 PC인지 특정할 수 없는 이유를 NAT의 동작으로 설명하세요.

**답:**

NAT(Network Address Translation)는 내부망의 사설 IP를 공인 IP로 변환하여 외부 인터넷과 통신할 수 있도록 하는 기술이다.

가정이나 회사에서는 여러 PC가 서로 다른 사설 IP를 사용하지만, NAT의 한 종류인 NAPT를 통해 하나의 공인 IP를 공유할 수 있다.

예를 들어 내부망의 두 PC가 인터넷에 접속한다고 가정한다.

- PC 1: `192.168.100.10`
- PC 2: `192.168.100.20`
- 공유기의 공인 IP: `1.245.252.171`

두 PC가 외부 서버에 접속하면 외부 서버에는 동일한 공인 IP인 `1.245.252.171`이 출발지 주소로 기록될 수 있다.

따라서 **외부 서버 로그에 남은 공인 IP만으로는 내부망의 어느 PC가 접속했는지 특정할 수 없다.**

정확한 내부 PC를 확인하려면 접속 시각, 출발지 포트 번호, 공유기나 방화벽의 NAT 변환 기록 등을 함께 확인해야 한다.

#### (다-2) 정적 NAT와 동적 NAT는 사설 IP와 공인 IP를 연결하는 방식이 어떻게 다른가요?

**답:**

**1. 정적 NAT(Static NAT)**

- 특정 사설 IP와 공인 IP를 1:1로 고정하여 연결하는 방식이다.
- 관리자가 미리 설정한 공인 IP가 계속 사용된다.
- 예: `192.168.100.10` ↔ `1.245.252.171`

**2. 동적 NAT(Dynamic NAT)**

- 여러 공인 IP를 미리 확보해 두고, 통신이 필요할 때 사용 가능한 공인 IP를 동적으로 할당하는 방식이다.
- 할당이 해제되면 해당 공인 IP를 다른 장치가 재사용할 수 있다.
- 예: `192.168.100.10` → 공인 IP 풀에서 `1.245.252.171` 할당

**결론:** 정적 NAT는 사설 IP와 공인 IP의 연결 관계가 고정되어 있고, 동적 NAT는 공인 IP 풀에서 사용 가능한 주소를 필요할 때 할당한다는 차이가 있다.

#### (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT를 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP로 PC를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.

**답:**

회사에서 사원 PC 여러 대가 인터넷을 사용할 때 동적 NAT를 사용하는 이유는 **한정된 공인 IP를 효율적으로 관리하기 위해서**이다.

정적 NAT는 사설 IP와 공인 IP를 1:1로 고정하지만, 동적 NAT는 공인 IP 풀에서 사용 가능한 주소를 필요할 때 할당하고, 할당이 해제되면 다른 PC가 재사용할 수 있다.

하지만 동적 NAT에서는 같은 공인 IP라도 접속 시각에 따라 서로 다른 PC에 할당될 수 있다.

따라서 외부 서버 로그에 기록된 공인 IP만으로는 어느 사원 PC가 접속했는지 정확히 특정하기 어렵다.

정확한 PC를 확인하려면 다음 정보를 함께 확인해야 한다.

1. **접속 시각:** 외부 서버에 접속한 정확한 시간
2. **NAT 변환 기록:** 해당 시각에 공인 IP가 어떤 사설 IP에 할당되었는지 확인
3. **DHCP 할당 기록:** 확인된 사설 IP가 당시 어느 PC에 할당되었는지 확인

실제 회사에서 여러 PC가 하나의 공인 IP를 동시에 공유한다면 동적 NAT보다 NAPT(PAT)를 사용하는 경우가 많다. 이때는 출발지 포트 번호와 NAT 포트 변환 기록도 함께 확인해야 한다.

#### (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT와 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.

**답:**

인터넷에서 회사 내부망의 웹 서버에 접속하도록 하려면 **정적 NAT(Static NAT)** 방식이 적합하다.

정적 NAT는 내부 웹 서버의 사설 IP와 외부에서 접근할 공인 IP를 1:1로 고정하여 연결하기 때문이다.

예를 들어 다음과 같이 설정할 수 있다.

- 내부 웹 서버의 사설 IP: `192.168.100.100`
- 외부에서 접속할 공인 IP: `1.245.252.171`
- NAT 연결: `192.168.100.100` ↔ `1.245.252.171`

이렇게 설정하면 외부 사용자가 공인 IP로 접속했을 때 NAT 장비가 목적지 주소를 내부 웹 서버의 사설 IP로 변환하여 요청을 전달할 수 있다.

반면 동적 NAT는 공인 IP를 필요할 때 할당하므로 특정 내부 서버에 항상 동일한 공인 IP가 연결된다는 보장이 없어 외부에서 지속적으로 접속해야 하는 웹 서버에는 적합하지 않다.

따라서 **내부 웹 서버는 외부에서 일정한 주소로 접근할 수 있어야 하므로 정적 NAT가 적합하다.**

실제 환경에서는 정적 NAT 대신 포트 포워딩(DNAT)을 사용하여 공인 IP의 80번 또는 443번 포트로 들어오는 요청을 내부 웹 서버로 전달하기도 한다. 또한 외부 접속을 허용하려면 방화벽 설정도 필요하다.

### 문제 3-1 · 내 서브넷 마스크 읽기

#### (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수

#### (가-2) 내 IPv4 주소의 망 부분 · 장비 부분

| 항목 | 결과 |

#### (나-1) 내 서브넷 마스크를 2진수로 펼쳤을 때 1인 비트와 0인 비트가 각각 주소의 어느 부분을 가리키는지, 1이 8개인 마디의 수를 근거로 설명하세요.

**답:**

서브넷 마스크 `255.255.0.0`을 2진수로 표현하면 다음과 같다.

`11111111.11111111.00000000.00000000`

- 1인 비트: 네트워크(망) 부분
- 0인 비트: 호스트(장비) 부분

1이 8개인 옥텟이 앞에서부터 2개이므로 총 16비트가 네트워크 부분이며, CIDR 표기는 `/16`이다.

따라서 내 IPv4 주소 `192.168.100.174`에서 앞의 `192.168`은 네트워크 부분이고, 뒤의 `100.174`는 호스트 부분이다.

#### (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1이 8개인 마디의 수를 넣어 설명하세요.

**답:**

내 서브넷 마스크는 `255.255.0.0`이며, 2진수로 표현하면 `11111111.11111111.00000000.00000000`이다.

1이 8개인 옥텟이 2개이므로 네트워크 비트 수는 다음과 같다.

`8 × 2 = 16비트`

따라서 내 서브넷 마스크의 **CIDR 표기는 `/16`**이다.

#### (나-3) 같은 교실의 다른 PC와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.

**답:**

같은 교실의 다른 PC가 동일한 `/16` 네트워크에 연결되어 있다면 망 부분은 같고, 장비 부분은 다르다.

내 IPv4 주소는 `192.168.100.174`이고, 서브넷 마스크는 `255.255.0.0 (/16)`이므로 망 부분은 `192.168`, 장비 부분은 `100.174`이다.

같은 망이란 서브넷 마스크를 적용했을 때 네트워크 주소가 같다는 뜻이다. 따라서 같은 망에 연결된 PC들은 망 부분이 같지만, 각 장비를 구별하기 위해 호스트 부분은 서로 다른 IP 주소를 사용한다.

#### (다-1) 내 마스크를 기준으로 `192.168.10.25`와 `192.168.20.25`가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.

**답:**

내 서브넷 마스크는 `255.255.0.0 (/16)`이므로 두 IP 주소는 같은 망에 속한다.

`/16`은 앞의 2개 옥텟이 네트워크 부분이라는 뜻이므로 첫 번째와 두 번째 옥텟을 비교해야 한다.

- `192.168.10.25` → 망 부분: `192.168`, 장비 부분: `10.25`
- `192.168.20.25` → 망 부분: `192.168`, 장비 부분: `20.25`

두 IP는 장비 부분은 다르지만 망 부분이 `192.168`로 같고, 네트워크 주소도 `192.168.0.0`으로 동일하다.

따라서 **같은 네트워크에 속한다.**

#### (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?

**답:**

`/24` 마스크(`255.255.255.0`)를 적용하면 두 IP 주소는 서로 다른 망에 속한다.

`/24`는 앞의 3개 옥텟이 네트워크 부분이므로 첫 번째부터 세 번째 옥텟까지 비교해야 한다.

- `192.168.10.25` → 망 부분: `192.168.10`, 네트워크 주소: `192.168.10.0`
- `192.168.20.25` → 망 부분: `192.168.20`, 네트워크 주소: `192.168.20.0`

두 주소는 세 번째 옥텟이 `10`과 `20`으로 다르므로 **서로 다른 네트워크에 속한다.**

#### (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.

**답:**

같은 망에 있는 장비끼리는 일반적으로 라우터를 거치지 않고 직접 통신할 수 있지만, 다른 망에 있는 장비와 통신하려면 라우터를 거쳐야 한다.

또한 방화벽은 IP 주소와 네트워크 범위를 기준으로 통신을 허용하거나 차단할 수 있다.

따라서 서브넷 마스크를 잘못 설정하면 통신 경로가 잘못 결정되거나, 방화벽에서 의도하지 않은 장비까지 허용 또는 차단할 수 있다.

즉, **서브넷 마스크를 정확히 이해해야 올바른 통신 경로와 보안 규칙을 설정할 수 있다.**

### 문제 4-1 · 반으로 나누기 `/25`

#### (가) 출력 두 줄

```text
192.168.50.0/25
192.168.50.128/25
```

#### (나-1) 4.1 표와 맞춰 쓴 블록마다의 범위

| 구분 | 첫 번째 블록 | 두 번째 블록 |
|---|---|---|
| 네트워크 주소 | `192.168.50.0/25` | `192.168.50.128/25` |
| 전체 주소 범위 | `192.168.50.0 ~ 192.168.50.127` | `192.168.50.128 ~ 192.168.50.255` |
| 사용 가능한 호스트 범위 | `192.168.50.1 ~ 192.168.50.126` | `192.168.50.129 ~ 192.168.50.254` |
| 브로드캐스트 주소 | `192.168.50.127` | `192.168.50.255` |
| 전체 주소 수 | 128개 | 128개 |
| 사용 가능한 호스트 수 | 126개 | 126개 |

**계산 근거:**

IPv4는 32비트이므로 `/25`에서 호스트 비트는 `32 - 25 = 7비트`이다.

따라서 블록당 전체 주소 수는 `2^7 = 128개`이며, 네트워크 주소와 브로드캐스트 주소를 제외하면 실제로 사용 가능한 호스트 주소는 블록당 126개이다.

#### (나-2) 블록 이름 `192.168.50.128/25`의 `/` 앞 주소는 그 블록에서 어떤 주소인가요? 설명하세요.

**답:**

`192.168.50.128/25`에서 `/` 앞의 `192.168.50.128`은 해당 블록의 **네트워크 주소(시작 주소)**이다.

이 주소는 네트워크 자체를 식별하는 데 사용하며, 일반적인 호스트에 할당할 수 없다.

#### (나-3) 두 블록이 `.128`에서 나뉘는 이유를 블록 하나의 주소 수로 설명하세요.

**답:**

`/25`는 호스트 비트가 7개이므로 블록 하나의 전체 IP 주소 수는 `2^7 = 128개`이다.

따라서 첫 번째 블록은 `192.168.50.0 ~ 192.168.50.127`까지 128개의 주소를 사용하고, 두 번째 블록은 그다음 주소인 `192.168.50.128`부터 시작한다.

즉, **블록 하나가 128개의 주소를 가지기 때문에 `.128`을 기준으로 두 네트워크가 나뉜다.**

#### (나-4) 쓸 수 있는 수(126)만큼씩 자르면 안 되는 이유를 설명하세요.

**답:**

`/25`는 호스트 비트가 7개이므로 블록 하나의 전체 주소 수는 `2^7 = 128개`이다.

이 중 네트워크 주소와 브로드캐스트 주소를 각각 1개씩 제외하면 실제로 사용할 수 있는 호스트 주소는 126개이다.

따라서 **네트워크를 나눌 때는 사용 가능한 호스트 수인 126개가 아니라 전체 주소 수인 128개를 기준으로 나눠야 한다.**

#### (다-1) 4.1 첫 표의 `/26` 줄에서 읽은 주소 수 · 장비에 쓸 수 있는 수

| 항목 | 결과 |
|---|---|
| 전체 IP 주소 수 | 64개 |
| 장비에 사용할 수 있는 주소 수 | 62개 |

#### (다-2) 두 수가 2만큼 다른 이유를 빠지는 두 주소의 역할로 설명하세요.

**답:**

`/26`의 전체 IP 주소는 64개이지만, 네트워크 주소와 브로드캐스트 주소를 각각 1개씩 제외하기 때문에 실제 장비에 사용할 수 있는 주소는 62개이다.

- **네트워크 주소:** 해당 네트워크 자체를 식별하는 주소
- **브로드캐스트 주소:** 같은 네트워크의 모든 장비에 데이터를 전달할 때 사용하는 주소

따라서 두 주소는 일반 장비에 할당할 수 없으므로 **64 - 2 = 62개**가 된다.

#### (다-3) 장비 64대인 부서에 `/26` 블록을 주면 어떤 설계 실수가 되는지 설명하세요.

**답:**

`/26` 블록은 전체 IP 주소가 64개이지만, 네트워크 주소와 브로드캐스트 주소를 제외하면 실제로 장비에 할당할 수 있는 주소는 62개이다.

따라서 장비가 64대인 부서에 `/26` 블록을 할당하면 **IP 주소가 2개 부족해 모든 장비에 주소를 할당할 수 없는 설계 실수**가 발생한다.

이를 해결하려면 사용 가능한 호스트 주소가 126개인 `/25` 블록을 할당해야 한다.

```text
True
```

- 개발팀: `192.168.50.0/25`
- 운영팀: `192.168.50.64/26`
- 두 네트워크의 주소 범위가 겹치므로 `True`가 출력된다.

#### (나-1) 운영팀을 `192.168.50.64/26`으로 바꾸자 `True`가 나온 이유를 두 망의 범위를 비교해 설명하세요.

**답:**

개발팀의 네트워크 `192.168.50.0/25`는 `192.168.50.0 ~ 192.168.50.127`까지이고, 운영팀을 변경한 `192.168.50.64/26`은 `192.168.50.64 ~ 192.168.50.127`까지이다.

두 네트워크는 `192.168.50.64 ~ 192.168.50.127` 범위의 IP 주소가 겹치기 때문에 `overlaps()` 함수의 결과가 `True`로 출력된다.

즉, **운영팀 네트워크가 개발팀 네트워크의 일부와 겹치므로 두 팀의 네트워크가 독립적으로 분리되지 않은 상태**이다.

#### (나-2) 두 망이 겹치는 주소 구간

**답:**

두 망이 겹치는 주소 구간은 **`192.168.50.64 ~ 192.168.50.127`**이다.

- 개발팀 (`192.168.50.0/25`): `.0 ~ .127`
- 운영팀 (`192.168.50.64/26`): `.64 ~ .127`

따라서 `.64 ~ .127`까지 총 64개의 IP 주소가 겹친다.

#### (다-1) 부서 망이 겹쳐 두 장비가 같은 IP 주소를 받으면 통신에는 어떤 문제가 생기는지 설명하세요.

**답:**

부서 망이 겹쳐 두 장비에 같은 IP 주소가 할당되면 **IP 주소 충돌(IP Conflict)**이 발생할 수 있다.

이 경우 네트워크에서 데이터를 어느 장비로 전달해야 하는지 혼란이 생겨 통신이 불안정해지거나 연결이 끊길 수 있다.

따라서 **부서별 네트워크가 겹치지 않도록 설계하고, 각 장비에 고유한 IP 주소를 할당해야 한다.**

#### (다-2) 같은 상황이 관제 로그 해석에는 어떤 문제를 일으키는지 설명하세요.

**답:**

부서 망이 겹쳐 두 장비가 같은 IP 주소를 사용하면, 관제 로그에 동일한 IP가 기록되어 어느 부서의 장비에서 발생한 통신인지 정확히 구분하기 어려워진다.

이로 인해 보안 사고가 발생했을 때 실제 문제를 일으킨 장비를 잘못 판단하거나, 공격 발생 위치를 추적하는 데 혼란이 생길 수 있다.

따라서 **부서별 네트워크를 겹치지 않게 설계하고 IP 주소를 고유하게 관리해야 관제 로그를 정확하게 분석할 수 있다.**

## 문제 5-1 · ARP 캐시에서 게이트웨이 찾기

### (가) 기본 게이트웨이 줄의 IP · MAC 주소 · `8.8.8.8` 줄이 있었나?

- 기본 게이트웨이 IP 주소: 미기입
- 기본 게이트웨이 MAC 주소: 미기입
- `8.8.8.8` 항목: 없음

### (나) `8.8.8.8`로 보냈는데도 ARP 캐시에 `8.8.8.8`이 없는 이유를 설명하세요.

**답:** 같은 로컬 네트워크의 장비는 ARP를 통해 MAC 주소를 확인하고 ARP 캐시에 저장한다. 반면 `8.8.8.8`은 외부 네트워크에 있으므로 직접 MAC 주소를 조회하지 않는다. 대신 기본 게이트웨이의 MAC 주소를 목적지로 설정하여 이더넷 프레임을 전송하기 때문에 ARP 캐시에 `8.8.8.8`이 나타나지 않는다.

### (다-1) MAC 주소와 IP 주소는 각각 누가 정하나요?

**답:** MAC 주소는 일반적으로 네트워크 장비 제조사가 부여하고, IP 주소는 네트워크 관리자가 직접 설정하거나 DHCP 서버가 자동으로 할당한다.

### (다-2) 패킷이 다른 망으로 건너갈 때 목적지 IP 주소와 MAC 주소가 바뀌는지 비교해 설명하세요.

**답:** 패킷이 다른 네트워크로 이동할 때 목적지 IP 주소는 최종 목적지를 나타내므로 일반적으로 그대로 유지된다. 반면 목적지 MAC 주소는 다음으로 전달할 장비의 MAC 주소로, 라우터를 거칠 때마다 새롭게 설정된다.

### (다-3) ARP가 MAC 주소를 알아낼 때 요청은 브로드캐스트로 보내고 응답은 한 장비만 하는 이유를 설명하세요.

**답:** ARP는 상대방의 MAC 주소를 모르기 때문에 같은 네트워크의 모든 장비에 브로드캐스트로 요청을 보낸다. 요청을 받은 장비 중 해당 IP 주소를 가진 장비만 자신의 MAC 주소를 응답하기 때문에 일반적으로 한 장비만 답한다.

## 문제 5-2 · 스위치의 MAC 주소 표 읽기

### (가) 첫 파일 출력 · 두 번째 파일(`"AA"`) 출력

**첫 번째 파일**

```text
모든 포트로
```

**두 번째 파일**

```text
포트 1 로만
```

### (나-1) 두 출력이 다른 이유를 MAC 주소 표의 내용과 5.3의 ② · ③ 단계로 설명하세요.

**답:** MAC 주소 표에는 `AA`가 1번 포트에 연결되어 있다는 정보만 저장되어 있다. 따라서 목적지가 `AA`이면 ②의 조건이 참이 되어 ③에서 `포트 1 로만` 출력된다. 반면 목적지가 `BB`이면 MAC 주소 표에 없으므로 조건이 거짓이 되어 `모든 포트로` 출력된다.

### (나-2) 둘째 출력에 `AA`가 아니라 숫자가 나온 이유를 딕셔너리의 키와 값으로 설명하세요.

**답:** 딕셔너리 `mac_table = {"AA": 1}`에서 `"AA"`는 **키(key)**이고, `1`은 **값(value)**이다. `mac_table[dest]`는 키에 해당하는 값을 가져오기 때문에 `"AA"`가 아니라 포트 번호인 `1`이 출력된다.

### (나-3) 그 숫자는 실제 스위치에서 무엇을 뜻하나요?

**답:** MAC 주소 표에 저장된 숫자는 해당 MAC 주소를 가진 장비가 연결된 스위치의 포트 번호를 뜻한다.

### (다-1) 플러딩은 어떤 조건에서 일어나나요?

**답:** 플러딩은 스위치가 목적지 MAC 주소를 자신의 MAC 주소 표에서 찾지 못했을 때 발생한다. 이때 스위치는 프레임을 수신한 포트를 제외한 같은 VLAN의 모든 포트로 전달한다.

### (다-2) 처음에는 플러딩하던 스위치가 그다음부터 한 포트로만 보내게 되는 과정을 설명하세요.

**답:** 처음에는 목적지 MAC 주소가 표에 없으므로 플러딩이 발생한다. 이후 목적지 장비가 응답 프레임을 보내면 스위치는 응답 프레임의 출발지 MAC 주소와 수신 포트 번호를 학습하여 MAC 주소 표에 저장한다. 그다음부터는 목적지 MAC 주소를 표에서 찾을 수 있으므로 해당 포트로만 프레임을 전달한다.

### (다-3) 플러딩이 많아지면 망의 성능과 보안에 각각 어떤 문제가 생기는지 예를 들어 설명하세요.

**답:**

- **성능 문제:** 플러딩이 많아지면 스위치가 여러 포트로 프레임을 전송하기 때문에 불필요한 네트워크 트래픽이 증가하고 통신 속도가 느려질 수 있다. 예를 들어 PC A가 PC B로 보내는 프레임이 여러 포트로 전달되어 대역폭을 불필요하게 사용한다.

- **보안 문제:** 프레임이 목적지 장비뿐 아니라 다른 장비에도 전달되므로 정보 노출 위험이 커진다. 예를 들어 같은 VLAN에 있는 공격자가 플러딩된 프레임을 수신하여 암호화되지 않은 통신 내용을 분석할 수 있다.

## 문제 6-1 · 내 PC의 기본 게이트웨이와 첫 홉

### (가) `ipconfig`의 기본 게이트웨이 주소 · `tracert` 1번 홉의 주소

- 기본 게이트웨이 주소: `192.168.1.1`
- `tracert` 첫 번째 홉 주소: `192.168.1.1`

### (나-1) 두 주소가 일치한다는 것은 이 PC의 트래픽 경로에 대해 무엇을 말해 주나요? 5.2의 「보낼 곳」 표와 이어서 설명하세요.

**답:** `tracert`의 첫 번째 홉과 기본 게이트웨이 주소가 `192.168.1.1`로 일치한다는 것은 외부 네트워크로 보내는 패킷이 기본 게이트웨이를 첫 번째 라우터로 거친다는 의미이다.

5.2의 「보낼 곳」 표처럼 같은 네트워크의 장비끼리는 직접 통신하지만, 다른 네트워크로 패킷을 보낼 때는 자신의 기본 게이트웨이를 이용한다.

### (나-2) 두 주소가 일치하지 않는다면 어떤 상황을 의심해야 하나요? 근거와 함께 설명하세요.

**답:** 기본 게이트웨이와 첫 번째 홉 주소가 다르다면 네트워크 설정이나 실제 라우팅 경로가 예상과 다를 가능성을 확인해야 한다.

- **라우팅 설정:** 더 구체적인 경로가 적용되어 다른 라우터로 전달되는 경우
- **VPN 사용:** VPN이나 가상 네트워크를 통해 다른 경로로 전달되는 경우
- **라우터 인터페이스:** 같은 라우터가 다른 인터페이스의 IP 주소로 응답하는 경우

단, 두 주소가 다르다고 반드시 네트워크 오류가 발생한 것은 아니다.

### (다-1) 기본 경로(`0.0.0.0/0`)는 어떤 목적지로 갈 때 쓰이나요?

**답:** 기본 경로는 라우팅 테이블에서 목적지 IP 주소와 일치하는 더 구체적인 경로를 찾지 못했을 때 사용한다. 일반적으로 외부 네트워크나 인터넷으로 패킷을 전달할 때 이용한다.

### (다-2) 기본 경로의 `/0`은 무엇을 뜻하나요?

**답:** `/0`은 네트워크 부분이 0비트라는 뜻으로, 모든 IPv4 주소와 일치하는 경로를 의미한다. 다만 더 구체적인 경로가 존재하면 해당 경로를 우선 사용한다.

### (다-3) 라우팅 표에서 기본 경로가 빠지면 맞는 줄이 없는 목적지로 가는 패킷은 어떻게 되나요?

**답:** 기본 경로가 사라지고 목적지와 일치하는 다른 경로도 없다면 패킷을 전달할 수 없어 폐기된다. 따라서 해당 외부 네트워크와 통신할 수 없게 된다.

### (다-4) 이때 같은 망 통신과 인터넷 통신이 각각 어떻게 되는지 이유와 함께 설명하세요.

**답:**

- **같은 망 통신:** 직접 연결된 네트워크 경로를 이용하므로 기본 경로가 없어도 통신할 수 있다.
- **인터넷 통신:** 기본 경로와 별도의 목적지 경로가 모두 없다면 패킷을 전달할 수 없어 인터넷 통신이 불가능하다.

## 문제 6-2 · 회사 망 줄인가, 기본 경로인가

### (가-1) 첫 번째 파일 출력

```text
맞는 줄: 192.168.30.0/24 → 직접 연결 VLAN 30
```

### (가-2) 두 번째 파일(`8.8.8.8`) 출력

```text
회사 망 줄에 없음 → 기본 경로 0.0.0.0/0 (인터넷 쪽 라우터)
```

### (나-1) 라우터가 `192.168.30.5`를 보낼 줄을 고르는 과정을 6.3의 라우팅 표와 첫 파일 출력으로 설명하세요.

**답:** 라우터는 목적지 IP 주소 `192.168.30.5`를 라우팅 표의 각 네트워크와 비교한다.

개발팀(`192.168.10.0/24`)과 운영팀(`192.168.20.0/24`)에는 포함되지 않지만, 보안팀(`192.168.30.0/24`)에는 포함된다.

따라서 `직접 연결 VLAN 30` 경로를 선택하여 해당 VLAN으로 패킷을 전달한다.

### (나-2) `8.8.8.8`일 때 `found`가 반복이 끝날 때까지 `False`로 남은 이유를 설명하세요.

**답:** 목적지 IP 주소 `8.8.8.8`은 라우팅 표에 등록된 개발팀, 운영팀, 보안팀 네트워크 중 어느 곳에도 포함되지 않기 때문이다.

따라서 `if dest in ipaddress.ip_network(net)` 조건이 모두 `False`가 되어 `found = True`가 실행되지 않는다.

결과적으로 반복문이 끝날 때까지 `found`는 `False`로 유지된다.

### (나-3) 그것이 라우터가 기본 경로 줄을 고르는 조건과 어떻게 대응하는지 설명하세요.

**답:** `found`가 `False`라는 것은 목적지 IP 주소와 일치하는 회사 네트워크 경로를 찾지 못했다는 의미이다.

이는 실제 라우터가 목적지와 일치하는 더 구체적인 경로를 찾지 못했을 때 기본 경로(`0.0.0.0/0`)를 선택하는 원리와 같다.

따라서 기본 경로가 설정되어 있다면 패킷을 인터넷 쪽 라우터로 전달한다.

### (다) 부서마다 VLAN을 나누면 한 부서 PC가 악성코드에 감염됐을 때 피해 범위와 대응 방법이 어떻게 달라지나요? 브로드캐스트 범위와 라우터에서의 접근 통제를 들어 설명하세요.

**답:** 부서마다 VLAN을 분리하면 한 부서의 PC가 악성코드에 감염되더라도 다른 부서로 피해가 확산될 가능성을 줄일 수 있다.

- **브로드캐스트 범위:** VLAN마다 브로드캐스트 도메인이 분리되므로 감염된 PC에서 발생한 브로드캐스트 트래픽이 다른 부서 VLAN으로 직접 전달되지 않는다.
- **라우터 접근 통제:** VLAN 간 통신은 라우터나 L3 스위치를 거치므로 ACL(접근 제어 목록) 등을 설정하여 감염된 부서에서 다른 부서로의 접근을 제한할 수 있다.

VLAN 분리만으로 악성코드 확산을 완전히 막을 수는 없으므로, 부서 간 접근 통제를 함께 적용해야 한다.

**핵심:** VLAN은 브로드캐스트 범위를 분리하고, 라우터의 접근 통제는 부서 간 통신을 제한하여 피해 확산을 줄인다.

### 문제 7-2 · 서브넷 마스크 다시 보기

- (가) 세 마스크의 CIDR · 주소 수:

- (나) 서브넷 마스크는 IP 주소에서 무엇을 정하는 값인가요? 마스크를 2진수로 썼을 때 1 과 0 이 각각 무엇을 뜻하는지 넣어 설명하세요.
  - 답:서브넷 마스크는 IP 주소에서 네트워크 부분과 호스트(장비) 부분을 구분하는 값이다.
서브넷 마스크를 2진수로 표현하면 다음과 같다.
- 1: 네트워크 부분을 의미하며, IP 주소가 어느 네트워크에 속하는지 구분한다.
- 0: 호스트 부분을 의미하며, 해당 네트워크 안에서 개별 장비를 구분한다.
예를 들어 255.255.255.0(/24)을 2진수로 표현하면 다음과 같다.

- (다) `172.16.8.40` 과 `172.16.9.40` 은 마스크가 `255.255.255.0` 이면 다른 망, `255.255.0.0` 이면 같은 망입니다. 같은 두 주소인데 판정이 달라지는 이유를 망 부분으로 설명하세요.
  - 답:같은 IP 주소라도 서브넷 마스크에 따라 네트워크 부분의 범위가 달라지기 때문에 같은 망인지 다른 망인지 판정이 달라진다.
- 255.255.255.0(/24): 앞의 3마디가 네트워크 부분이다. 172.16.8과 172.16.9가 서로 다르므로 다른 네트워크에 속한다.
- 255.255.0.0(/16): 앞의 2마디가 네트워크 부분이다. 두 주소 모두 172.16이 같으므로 같은 네트워크에 속한다.
핵심: 서브넷 마스크가 어디까지를 네트워크 부분으로 지정하느냐에 따라 동일한 두 IP 주소도 같은 망 또는 다른 망으로 판단될 수 있다.

- (라) 원래 `/24` 로 써야 하는 PC 에 실수로 `255.255.0.0` 을 설정하면, 그 PC 가 `172.16.9.40` 으로 보낼 때 어떤 문제가 생길지 게이트웨이와 이어서 설명하세요.
  - 답:PC 172.16.8.40이 원래 /24를 사용해야 하는데 실수로 /16을 설정하면, 목적지 172.16.9.40을 같은 네트워크에 있다고 잘못 판단한다.
따라서 기본 게이트웨이로 패킷을 보내지 않고 ARP를 이용해 직접 통신하려고 한다. 실제로 두 PC가 서로 다른 VLAN에 있다면 ARP 요청이 전달되지 않아 통신에 실패할 수 있다.
핵심: 서브넷 마스크를 잘못 설정하면 다른 네트워크의 장비를 같은 네트워크로 판단하여 기본 게이트웨이를 사용하지 않는 문제가 발생할 수 있다.
