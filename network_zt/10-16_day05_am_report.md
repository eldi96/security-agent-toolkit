## 4교시 · 구역 규칙 코드

### 문제 4-1 · 규칙 판정 코드 읽고 설명하기

- (가) 함수 `default_policy` · `match_rule` · `judge` 가 각각 무엇을 하는지 적어 주세요.
  - 쓸 내용: 「default_policy: … / match_rule: … / judge: …」 함수마다 자유롭게
  - 답:
    - default_policy: 일치하는 방화벽 규칙이 없을 때 출발 구역과 도착 구역을 확인하여 통신을 허용하거나 차단하는 함수이다.
    - match_rule: 요청의 출발 구역, 도착 구역, 포트가 방화벽 규칙과 모두 일치하는지 확인하는 함수이다.
    - judge: 방화벽 규칙을 위에서부터 순서대로 확인하고, 일치하는 규칙이 있으면 해당 규칙의 동작과 번호를 반환하는 함수이다. 일치하는 규칙이 없으면 기본 정책을 적용한다.

- (나) `judge` 가 리턴하는 값 두 개는 무엇이고, 어느 줄이 만드나요?
  - 쓸 내용: 「값 ①: … / 값 ②: … / 만드는 줄: …」
  - 답:
    - 값 ①: 통신 허용(`permit`) 또는 차단(`deny`) 결과
    - 값 ②: 적용된 방화벽 규칙 번호
    - 만드는 줄: `return rule[4], rule[0]`
    - 일치하는 규칙이 없으면 `return default_policy(src, dst), 0`에서 기본 정책 결과와 규칙 번호 0을 반환한다.

- (다) 🔍 `judge` 의 `for` 는 맞는 규칙을 찾으면 바로 `return` 합니다. 같은 요청에 규칙이 둘 이상 맞는다면 어느 규칙이 적용되나요? 왜 `return` 으로 바로 끝내도록 만들었나요?
  - 쓸 내용: ① 규칙이 둘 이상 맞을 때 적용되는 규칙 ② 방화벽이 「첫 번째로 맞는 규칙」을 쓴다는 점과 이어서 `return` 으로 바로 끝내는 이유
  - 답: 여러 규칙이 일치하면 규칙표에서 가장 먼저 일치하는 규칙이 적용된다. 방화벽은 규칙을 위에서부터 순서대로 검사하므로 첫 번째로 일치하는 규칙을 찾으면 `return`으로 판정을 끝낸다. 이후 규칙을 검사하지 않아 먼저 적용된 규칙의 판정 결과를 유지하기 위해서이다.
